# Part 1
# AI 的資料結構設計

---

## AI 怎麼「讀懂」你給的東西？

AI 不像人類有長期記憶。

每次對話，AI 只能看到一個**「工作桌」**裡的內容
→ 這個工作桌叫做 **Context Window（上下文窗口）**

> 你放什麼在桌上、怎麼放，決定了 AI 表現的好壞

---

## Context Window 的比喻

```
┌─────────────────────────────────────────┐
│          AI 的工作桌（有限空間）           │
│                                         │
│  📋 公司背景說明          （系統層）      │
│  📚 產品知識 / 術語表     （知識層）      │
│  ✉️  你今天的問題         （任務層）      │
│                                         │
│  ← 放越清楚，AI 理解越快 →               │
└─────────────────────────────────────────┘
```

**桌面有大小上限（Token 限制）**
→ 精準放資料比全部塞進去更重要

---

## 三層資料架構

| 層次 | 名稱 | 放什麼 |
|------|------|--------|
| **第一層** | 系統層（System） | 公司背景、AI 的角色與限制 |
| **第二層** | 知識層（Knowledge） | 產品介紹、SOP、術語定義 |
| **第三層** | 任務層（Task） | 你今天具體要 AI 做什麼 |

> 類比：員工手冊（第一層）+ 專業訓練（第二層）+ 今天的工作清單（第三層）

---

## 結構差 vs 結構好

| 結構差的做法 | 結構好的做法 |
|------------|------------|
| 一大段沒標題的文字 | 有 `#標題` 的分類文件 |
| 全部資訊一次塞進去 | 分層次依需要提供 |
| 沒有定義 AI 的角色 | 明確告訴 AI「你是誰」 |
| 術語沒解釋 | 附上術語表 |
| 沒有輸出格式要求 | 指定字數、格式、語氣 |

# Part 2
# 讓 AI 秒懂你的公司

---

## 為什麼 AI「不認識」你的公司？

- AI 訓練資料截止有時間點，**內部資訊不在其中**
- 你的產品名稱、內部術語、SOP → **AI 完全不知道**
- 就算知道，也可能是**過時的公開資訊**

**解法：自己寫一份「公司說明書」給 AI**

---

## 公司說明書模板

```markdown
# 公司背景
- 公司名稱：XX 科技
- 產業：B2B SaaS / 電商 / 製造業...
- 核心業務：[用 1-2 句話說清楚]
- 目標客群：[誰是你的客戶]

# 核心產品 / 服務
- [產品 A]：[一句話說明功能]
- [產品 B]：[一句話說明功能]

# 術語對照表
- [內部術語]：[實際意思]

# 溝通語氣
正式 / 友善 / 專業  →  請選一個並描述
```

---

## 說明書怎麼用？

**▸ 短期使用（馬上可以做）**
每次對話開頭，把公司說明書貼在最前面

**▸ 中期使用（建議建立）**
在 Claude / ChatGPT 設定 **System Prompt**
→ 每次對話自動帶入，不用重複貼

**▸ 長期進階（未來目標）**
建立 **知識庫（RAG）**
→ 公司文件、產品手冊讓 AI 即時查詢

---

## 實際比較：加說明書前 vs 後

**問題：「幫我回覆客戶詢問產品升級的問題」**

❌ **沒有說明書**
> AI：請問您是指哪個產品？升級的費用和方式因方案而異...

✅ **有說明書**
> AI（已知公司背景）：您好，感謝詢問 [產品名] 的升級方案。我們目前提供 Standard → Pro 的升級路徑，可至後台一鍵升級，費用將按比例計算剩餘天數...

# Part 3
# Prompt 怎麼寫才有效

---

## 一個好 Prompt 的四個要素

### R.C.T.F. 框架

| 要素 | 英文 | 你要告訴 AI 什麼 |
|------|------|----------------|
| **角色** | Role | 你是一位...（賦予 AI 身份） |
| **背景** | Context | 情境說明（公司、對象、狀況） |
| **任務** | Task | 具體要做什麼 |
| **格式** | Format | 輸出長度、形式、語氣 |

---

## 示範：改造一個 Prompt

**改造前（模糊）**
> 幫我寫一封信

---

**改造後（RCTF）**

> **[角色]** 你是我們公司的客服主管。
>
> **[背景]** 我們的 SaaS 平台昨天發生 2 小時服務中斷，影響約 50 位企業客戶。
>
> **[任務]** 請草擬一封道歉暨說明信，包含：事件描述、影響範圍、後續改善措施。
>
> **[格式]** 正式但誠懇的語氣，300 字以內，段落分明。

---

## 讓 Prompt 更精準的技巧

**1. 給範例（Few-shot）**
> 「請用以下格式回覆：[範例]」

**2. 限制範圍**
> 「只回答與我們產品相關的問題，其他請說不知道」

**3. 要求思考過程**
> 「請一步一步解釋你的推理再給出答案」

**4. 角色扮演驗證**
> 「用我們的新客戶角度，檢查這份說明書是否清楚」

---

## 常見錯誤 × 四個地雷

❌ **一次問太多問題**
→ 分開問，每次只問一件事

❌ **沒說輸出給誰看**
→ 說清楚對象：「給不懂技術的主管看」

❌ **期待 AI 猜到你的背景**
→ 沒說的事 AI 不知道，說了才會用

❌ **拿到第一個答案就算完成**
→ Prompt 是迭代的，繼續追問、修正

---

## 迭代心態：Prompt 不是一次到位

```
你的第一個 Prompt
        ↓
AI 的回應（可能不夠好）
        ↓
你的追問 / 修正指令
  「把第二段改得更口語一點」
  「再加一個實際案例」
  「換成條列式」
        ↓
越來越接近你要的結果
```

> 跟 AI 對話就像跟實習生工作 — 需要引導，不是命令

---

## 今日三大重點回顧

**1️⃣ 三層結構**
系統層（角色）→ 知識層（公司背景）→ 任務層（今日任務）

**2️⃣ 公司說明書**
讓 AI 秒懂你的業務，System Prompt 一次設定

**3️⃣ RCTF 框架**
Role × Context × Task × Format — 每個 Prompt 的骨架

---

## 實戰練習

**現在試著為你的工作場景寫一個 Prompt：**

```

格式（Format）：_______________ 字以內，

```
