## 課程涵蓋的設計模式

### 行為型模式 (Behavioral Patterns)

**策略模式 (Strategy Pattern)**
用於處理「原始型」的行為變動性，允許從外部動態抽換或擴充不同的演算法與行為，而不必修改既有的核心程式碼。

**樣板方法 (Template Method)**
透過「留同存異」將重複的程式碼提取到父類別中，並將變動的步驟設為抽象或掛鉤交由子類別實作，是實踐「控制反轉 (IoC)」的基礎手法。

**責任鏈模式 (Chain of Responsibility)**
用於處理「輸入比對型」的行為變動，將多個處理者串聯成一條鏈，讓請求沿著鏈傳遞，直到被對應的處理者攔截並處理。

**觀察者模式 (Observer Pattern)**
用於處理「響應式行為」，當主體物件的狀態發生改變時，會主動通知所有已註冊的觀察者物件以進行狀態更新或後續動作。

**指令模式 (Command Pattern)**
將每一道指令及其執行行為封裝成獨立的物件，藉此解耦「操作」與「能力」，並能輕易地實作「復原 (Undo)」與「重做 (Redo)」功能。

**狀態模式 (State Pattern)**
用於梳理複雜的行為變化，處理物件在不同狀態下會有不同反應的邏輯。

### 結構型模式 (Structural Patterns)

**門面模式 / 表象模式 (Facade Pattern)**
提供一個簡單俐落的「門面」類別來封裝隱藏系統內部繁雜的結構與多個介面，大幅降低使用者的學習門檻並提高套件的易用性。

**裝飾者模式 (Decorator Pattern)**
透過物件組合的方式來動態疊加行為（例如：走、跳、跑、追、打的任意組合），有效解決類別過度繼承所造成的「組合爆炸」難題。

**轉接器模式 (Adapter Pattern)**
用以解耦核心領域模組與外部依賴（如不同的資料庫 Driver），使原本介面不相容的類別能夠合作無間。

### 創建型模式 (Creational Patterns)

**工廠方法 (Factory Method)**
將物件的創建職責交給子類別或特定工廠方法來決定，藉此處理系統中物件生命週期的約束。

## 核心原則

### 開閉原則 (Open-Closed Principle, OCP)
- 核心痛點：不遵守會導致開發新功能時需要不斷修改既有程式碼，增加「認知負擔」，引發「雙層產能惡性循環」
- 實務觀點：不應視為死板教條，否則會導致「過度設計 (Over-Design)」
- 應用時機：主概念在領域中極為重要，且能預測「從概念」有大量擴充需求時

### 依賴反轉原則 (Dependency Inversion Principle, DIP)
- 核心定義：高層次（核心）的模組不能夠依賴低層次（衍生）的模組，兩者之間只能夠依賴一個抽象
- 落地手法：「依賴反轉之重構三步驟」：(1) 封裝變動之處、(2) 萃取共同行為、(3) 委派
- 重要性：套用八成設計模式的殺手級底層邏輯

## 方法論

### 水球流 OADP — 疊代式開發框架
OOA → OOD → OOP 的系統化流程，幫助工程師把無形的領域知識化為高維護性的程式碼。

#### OOA (物件導向分析)
不考慮程式實作，只專注於將無形的知識萃取並結構化。
透過「單句分析」依序執行：
- 點的萃取：辨識具備特定意義的詞彙，分類為物件、類別或屬性
- 區分結構、行為和侷限：定義實體的職責 (What)、具體行為 (How)、操作 (Operation)、侷限 (Constraints)
- 線的萃取：推導依賴、關聯、聚合、複合與繼承關係，定義基數 (Multiplicity)

#### OOD (物件導向設計)
目標：將 OOA 產出的領域模型加工成「好實作、好維護的設計藍圖」。
- 先求跑：利用循序圖 (Sequence Diagram) 模擬物件互動，梳理主流程
- 再求好：基於「最小知識原則」進行封裝、解耦、萃取
- 套用模式：利用 Christopher Alexander 的模式思維 (Context → Forces → Problem → Solution → Resulting Context) 精準評估並套用設計模式

#### Clean Architecture 大道至簡
兩大底層邏輯方針：
1. **封裝變化**：將「會一起變的、變法相同的」類別放進同一個模組
2. **單向穩定依賴原則**：永遠由易變的衍生模組依賴穩定的高階模組

## 課程架構與學習路徑

### 🥋 白段道館（紮實基礎）
- Ch 1. 行雲流水的設計底層思路：OOA、OOD、OOP 基礎功
- Ch 2. Christopher Alexander 設計模式：OCP 開閉原則 + 策略模式 + 依賴反轉三步驟
- Ch 3. 樣板方法 (Template Method)：控制反轉 (IoC) 基礎框架思維
- Ch 4. 複雜行為實戰 (Big 2)：策略模式 vs 責任鏈模式的 Forces 差異
- Ch 5. 多重設計難題實戰 (RPG)：觀察者 + 指令 + 狀態模式

### 🥋 黑段道館（進階架構）
- Ch 6. 基礎架構思維：門面模式 + Clean Architecture 模組化
- Ch 7. 透過複雜結構組合行為：裝飾者模式
- Ch 8. 高級複雜框架實戰：有限狀態機框架 (FSM)
- Ch 9. 生命週期約束：工廠方法
- Ch 10. 期末專案：開發 Web Framework
