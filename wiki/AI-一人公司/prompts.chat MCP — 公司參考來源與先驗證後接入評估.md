# prompts.chat MCP — 公司參考來源與先驗證後接入評估

## 結論與授權範圍

建議先把 prompts.chat 當作候選參考來源，用少量真實任務比較效益，再決定是否接 MCP。值得參考不等於值得立即安裝。MCP 主要降低搜尋與取用的操作成本，不能據此推論產出品質會改善。

本頁保存 2026-09-19 對話中的評估及修正建議。使用者本次授權寫入 Wiki；不代表核准執行比較試驗、安裝 MCP、修改公司流程、上傳資料或發布。先前「先接唯讀 MCP 試用」的建議修正為「先驗證參考價值，再決定是否接線」。

## 已核對的官方資訊

- 官方 API 文件列出 search_prompts、get_prompt；公開內容查詢可免 API key。save_prompt、improve_prompt 與部分 Skill 寫入功能需要認證。[API 文件](https://prompts.chat/docs/api)
- 提供 Remote HTTP 與本機 stdio 路線。本機 npx 啟動方式仍連接遠端服務，不能視為離線提示詞庫。[MCP repository](https://github.com/f/prompts.chat-mcp)
- API 文件與 MCP repository README 列出的工具範圍不完全相同；實際可用能力須在接入時核對握手、工具清單與客戶端支援。文件不是本機連線證據。
- 未提供 API key 能限制需要認證的功能，但不等於已建立只允許搜尋／讀取的技術邊界。若後續安裝，應確認客戶端能否限定 search_prompts、get_prompt；不能只靠提示詞聲稱唯讀。

## 前次建議需要補正的地方

| 原先漏想或不夠精確處 | 修正 |
|---|---|
| 有參考價值就值得安裝 | 先確認是否改善現有角色的成果；取用便利與內容價值分開判斷 |
| 免登入等於唯讀限制完成 | 認證限制、客戶端工具限制、查詢資料傳輸要分開核對 |
| 三稿盲讀足以證明外部提示詞有效 | 保留未受外部提示詞影響的基準稿，否則只能比較稿件偏好 |
| 找到好提示詞就納入公司方法 | 核對來源、適用條件、重用條款與跨題目效益；不整庫搬入 |
| MCP 應成為出稿固定步驟 | 僅在缺切角或首次遇到文體時使用；離線或無結果仍照既有流程完成 |

## 建議的小型比較方式（尚未執行）

1. 選三個實際會做的任務，例如文章開頭、產品說明、研究摘要，使用公開或合成素材。
2. 每題先保留一份既有方法產出的基準稿，再查最多兩份相關提示詞，由原角色借用有價值的結構產出另一份。固定需求、來源、模型與大致篇幅。
3. 透過 draft-review 盲讀。若使用目前三稿介面，第三稿可用既有方法另產一次，避免把一般生成差異全歸功於外部參考。
4. 比較需求符合度、無根據敘述、需要修改的位置與數量，以及搜尋和修訂額外時間。先作選擇與理由記錄，再揭曉來源。
5. 建議門檻：至少兩題有可指出的改善、沒有新增重大事實或授權問題，且額外時間可接受。這是小型試用的決策門檻，不是統計證明或通用品質認證。
6. 若僅個別模板有效，整理少量本地參考即可；只有持續有用且經常搜尋，才值得安裝 MCP。

## 接入方式比較

| 方式 | 適用時機 | 取捨 |
|---|---|---|
| 按需查網站、保留來源連結 | 現階段優先 | 無新增設定負擔，取用較手動 |
| Remote MCP | 驗證有效且常用後 | 搜尋方便，但增加外部依賴、查詢傳輸與維護 |
| 少量已驗證的本地方法 | 穩定重用時 | 可攜且可離線；須保留來源、日期與適用範圍 |

## 公司流程與資料界線

任務與限制 → 必要時搜尋參考 → 原交付角色篩選改寫 → 候選稿比較與回饋 → 原品質驗收。

- 既有方法足夠時直接完成，不強制搜尋、不新增員工或第二份發布帳本。
- 搜尋只送一般需求與關鍵字；不送客戶名稱、私人稿件、對話紀錄或整份專案資料。遠端查詢本身也會傳送資料。
- 外部提示詞是參考材料，不覆蓋公司角色分工、授權或資料契約；不直接執行取得的 Skill 腳本。
- 初期不啟用 save_prompt、improve_prompt、Skill 寫入／安裝，避免增加外部保存位置與重複能力。
- 經真案確認且使用者核准後，才把通用方法整理至原有角色方法文件；單篇偏好不自動寫入 Memory 或品牌規則。
- 可攜版不將 MCP 列為必裝項目；未安裝、離線或搜尋失敗時，既有工作流程仍須可用。
- 涉及報告版型、網頁或軟體畫面，仍先產圖片選視覺方向，確認後才實作；文字盲讀不能代替視覺確認。
