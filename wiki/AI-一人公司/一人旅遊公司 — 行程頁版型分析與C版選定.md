# 一人旅遊公司 — 行程頁版型分析與 C 版選定

> [!important] 已選 C：行程週覽
> 使用者明確回覆：「把上面的分析及template A/B/C寫進Wiki. 我選C」。
> C 為後續行程頁整合的選定方向；A／B 保留作設計比較。這次完成 Wiki 歸檔與選版紀錄，正式 Dashboard 尚未整合 C。

## 1. 要解決的問題

使用者希望行程頁簡單、專業，能在短時間內理解去哪裡、怎麼走、吃什麼、住哪裡及花多少。先前問題包括：首頁資訊零碎、交通文字太長、費用被拆成難以理解的項目，以及來源與原始時間搶走閱讀重點。

設計順序因此採用：**全程總覽 → 每日行程 → 機票住宿 → 費用 → 行前準備**。先回答顧客問題，再展開地址、交通、條款與來源；不要求顧客替 AI 填完規劃資料。

## 2. Notion 模板參考分析

本次先前研究實際查看 Marketplace 說明及可見預覽，未操作模板內部完整資料庫；以下不代表已驗證全部功能。

模板是資訊组织參考；公司的價格適用範圍、旅客人數、房型、票種、來源、訂購狀態仍須保留。沒有安裝 Notion2Booklet、購買模板、登入或搬移旅客資料到 Notion。

## 3. A／B／C 互動預覽

三版均取自同一份關西親子五日 v1 資料，保留草案與未確認標示。HTML 為本次原創，並非第三方模板副本。

| 版型 | Wiki 保存的 HTML | 主要排列 | 適合情境 | 取捨 |
|---|---|---|---|---|
| A・旅行手冊 | [開啟 A](assets/travel-templates-20260910/booklet.html) | 五天重點由上而下，住宿基地與預算並排 | 初次了解全程 | 閱讀順序明確，但跨日比較需要上下看 |
| B・每日路線 | [開啟 B](assets/travel-templates-20260910/dayguide.html) | 預設第 2 天，時間軸搭配順序示意與當日費用 | 旅途中查閱當天資訊 | 當日資訊集中，全程輪廓需回總覽 |
| **C・行程週覽：已選定** | **[開啟 C](assets/travel-templates-20260910/weekboard.html)** | 桌面五天並排；每欄含日期、重點及當日預留費用；窄螢幕以 CSS 改為上下排列 | 比較每天安排、討論節奏與花費 | 跨日比較直覺；天數變多時需另外處理分組，尚未完成長行程驗證 |

每頁頂端可以切换 A／B／C，保留分區與所選日期。三版都能切換五天、展開地址及交通提醒、比較機票住宿、查看每日費用長條圖，並開啟供應商入口。沒有下訂、勾選即通過或修改正式旅程的功能。

HTML 包含既有私人行程快照，**僅保存於本機 Wiki，不作公開範本發行**。價格為先前查閱與規劃資料，本次未重新查價；正式來源仍在公司 trip.json。三份 HTML 放同一個資料夾，才能保留彼此切換的相對連結。若 Obsidian 顯示 HTML 原碼，請從檔案所在資料夾用一般瀏覽器開啟。

## 4. 已選方向與原建議的區別

- AI 原先建議先看 A，再参考 B 的每日資訊。
- **使用者最終選擇 C；後續以 C 為主，不沿用 AI 原先偏好 A 的建議。**
- A／B 保存供比較，不另立兩份正式行程。
- 本次選定 C 不等於正式 Dashboard 已換版，也不等於授權發布、提交、推送或外部服務寫入。

## 5. 後續整合應保留的設計原則

```text
C：全程週覽
  日期／城市／當日重點／當日費用
                    ↓ 點一天
  每日時間軸 → 交通、地址、餐飲、訂票細節
                    ↓ 需要比較時
  機票住宿／費用／行前準備
```

1. 每天先顯示至多三個重點，完整順序及移動放進每日頁。
2. 城市順序用示意圖、每日安排用時間軸、費用用長條圖；沒有可靠地理資料不能把連線當成實際導航。
3. 餐館旁放菜色與訂位，景點旁放購票，交通旁放走法；重要限制如過敏待確認仍留在相關項目。
4. 每日花費與全程共同費用分開；預留額、查得價與完整報價不得混稱。
5. 手机以當日資訊與垂直排列為主，避免橫向拖動大型表格。此為設計目標，目前尚未實機驗收。
6. 一份正式旅程資料產出不同閱讀方式，避免另建 Notion 或手冊資料副本作第二個正式來源。

## 6. 已驗證與未驗證

- 原試作產製成功；Node VM 模擬 DOM 共 106 項斷言通過，包含導航、五天內容、費用加總、連結、文字逸出與資料快照。這是先前試作紀錄，非本次重新執行結果。
- 原正式 trip.json 的 hash 保持不變；manifest 保存旅程版本與來源 hash。
- 原試作開頁工具回 queued；Browser Use 因 URL 安全政策阻擋 file 網址，未繞過。
- 桌面／手機視覺、真 DOM 操作、真人、螢幕閱讀器及列印尚未驗證。
- 本次 Wiki 保存結果與副本一致性見同資料夾 verification.json；程式通過不能當供應商資訊正確或已可出發。
