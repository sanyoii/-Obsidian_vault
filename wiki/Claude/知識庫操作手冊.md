## 系統角色

這個 Vault 是一座**由 LLM 編譯、維護的知識庫**。Claude Code 在此扮演「LLM 編譯器」角色，負責：
1. 讀取 `raw/` 的原始文件
2. 編譯、整理成 `wiki/` 的結構化知識庫
3. 回答查詢並將結果存回 `output/`
4. 定期執行 lint 維護知識庫品質

所有輸出一律使用**繁體中文**。

## 目錄結構

```
vault/
├── raw/
│   ├── sources/        ← 原始文件（PDF、網頁剪報、論文）
│   └── notebooklm/     ← NotebookLM 匯出（FAQ、Study Guide）
├── wiki/
│   ├── _index.md       ← 主索引
│   ├── _summaries.md   ← 所有文章摘要
│   ├── _graph.md       ← 概念連結圖
│   ├── Claude/         ← Claude / 系統相關文章
│   └── concepts/       ← 其他結構化概念文章
├── output/
│   ├── queries/        ← /query 答案輸出
│   └── slides/         ← /slide 投影片輸出
└── scripts/
    └── search.py       ← 全文搜尋 CLI
```

### raw/ 兩種來源的處理差異

| 子目錄 | compile 策略 |
|--------|-------------|
| `sources/` | 從頭萃取概念，LLM 自行判斷結構 |
| `notebooklm/` | 以 NotebookLM 的層級結構為骨架，`sources/` 補充細節 |

同一主題同時有兩種來源時，優先以 `notebooklm/` 結構為骨架。

## 指令集

### `/compile` — 編譯新文件

讀取 `raw/` 中尚未處理的文件：
1. 掃描 `raw/notebooklm/` → 以其結構為概念文章骨架
2. 掃描 `raw/sources/` → 補充細節、引述原文
3. 在 `wiki/concepts/` 建立或合併概念文章
4. 更新 `_index.md`、`_summaries.md`、`_graph.md`
5. 在原始文件第一行加上 `<!-- processed: YYYY-MM-DD -->` 標記

### `/query <問題>` — 研究查詢

跨越整個 `wiki/` 回答複雜問題：
1. 讀 `_index.md` 定位相關文章
2. 深入閱讀相關 wiki 文章
3. **若資料不足：** 用 `notebooklm-skill` 查詢 NotebookLM，取得補充
4. 撰寫完整答案存至 `output/queries/YYYY-MM-DD_<標題>.md`
5. 補充資訊存至 `raw/notebooklm/YYYY-MM-DD_query-supplement_<標題>.md`
6. 更新 `_graph.md`（若發現新連結）

> NotebookLM 是「線上擴充資料庫」：查詢結果自動回流 `raw/` → 下次 `/compile` 進入 wiki，形成持續成長的迴圈。

### `/lint` — 維護知識庫

掃描 `wiki/concepts/` 執行：
1. 找出資料不一致（互相矛盾的描述）
2. 找出缺失資訊（`TODO:` 或空白段落）
3. 補充未連結的相關概念到 `_graph.md`
4. 提出 3–5 個值得探索的問題，存至 `output/lint_<日期>.md`

### `/slide <主題>` — 產生投影片

從 wiki 萃取內容，產生 Marp 格式投影片存至 `output/slides/`。

### `/search <關鍵字>` — 快速搜尋

在 `wiki/` 全文搜尋關鍵字，回傳命中的文章片段。

## 文件優先順序

讀檔時：
1. `wiki/_index.md` — 先看索引定位
2. `wiki/_summaries.md` — 快速了解摘要
3. `wiki/Claude/` 或 `wiki/concepts/<相關文章>.md` — 深入閱讀
4. `raw/notebooklm/<文件>` — 預消化筆記
5. `raw/sources/<文件>` — 原始第一手資料

---

## 注意事項

- 永遠不要刪除 `raw/` 的原始文件
- 每次 compile 後必須更新三個索引（`_index`、`_summaries`、`_graph`）
- 概念文章應包含 `## 反向連結` 區塊
- 查詢答案要標注來源（哪篇 wiki 文章或 NotebookLM）
- `/query` 從 NotebookLM 取得的補充資訊必須存回 `raw/notebooklm/` 才算完成
