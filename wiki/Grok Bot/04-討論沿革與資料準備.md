# Grok Bot — 討論沿革與資料準備

本頁保留需求如何演變、設定為什麼修改，以及 About Me 的資料準備結果。原始需求、使用者貼出的八個 description、各次完整回答另存 [[raw/sources/2026-09-12-grok-bot-discussion|Grok Bot 討論來源紀錄]]。原始紀錄中的六角色方案及審查前文字屬歷史版本；可貼入版本以 [[Grok Bot/03-Bot完整設定]] 為準。

## 討論沿革

| 階段 | 使用者需求與處理 | 保留的結論 |
|---|---|---|
| 1．閱讀八份官方文件 | 指定使用 decision-ready-answer，依個人需要規劃團隊 | 初始六個角色：CoS、Hunter、Resume、Assistant、Architect、QA |
| 2．審查 About Me | 檢查資料能否支援求職與 Bot 設定 | 五個檔案須處理；先審查，當時未修改 |
| 3．依建議修改 | 使用者明確授權五個檔案的修正 | 本機修改完成；歷史驗證紀錄有 32／32 靜態與內容檢查通過 |
| 4．Grok 是否能讀取 | 釐清 Codex、本機與 Grok 的存取差異 | 不自動共享；須上傳、connector 或另行核准本機能力 |
| 5．加入 Tutor | 學 Python、Web3、Crypto、投資金融等；分章圖解、即時答疑與出題 | Tutor 獨立負責教學與學習驗收 |
| 6．Review 八角色設定 | 使用者貼出包含 Apply Bot、生活預訂與 Tutor 的配置 | 保留八角色；修授權、主張、交接及停止狀態 |
| 7．完整補強 | 使用者要求每個 description 個別列出 | 八份可貼入完整設定，統一角色名稱 |
| 8．Wiki 歸檔 | 整理所有 Grok 資訊，追加要求獨立分類 | 放入 wiki/Grok Bot；不放在 AI-一人公司分類底下 |

## 八角色 review 的發現與修正

| 原設定問題 | 可能結果 | 補強方式 |
|---|---|---|
| Assistant「需授權或已連 Calendar」 | 把工具連接當成寫入授權 | 已連接只代表可用；有指定行事曆的完整既有授權可直接執行 |
| Resume「有證據、可重算方法或核准清單」 | 未核准公開的數字重新進履歷 | 必須符合目前核准用途與限制；可重算不等於可公開 |
| Hunter 後直接進 Apply | 缺客製化履歷判斷、缺最終紀錄負責人 | 先判斷沿用或製作履歷，必要時審查；CoS 在授權內更新唯一 tracker |
| 「草稿」與網站填入混用 | 網站可能在 Submit 前儲存資料 | 預設草稿在對話／工作檔；填入、上傳、送出分別依授權 |
| Unknown 未交代用途 | 把未知狀態當實際申請答案 | 僅作內部標記；缺必要事實時回報 |
| Assistant 與 Apply 都能寫招募信 | 重複草稿甚至重複寄送 | 依事情分工；混合信件一個主責 |
| 「達停止條件即結案」 | 額度或時間用完也被說完成 | 完成、待輸入、待授權、受阻、達上限分開 |
| 一輪製作／審查未寫修正 | 有發現卻無修正，或無限往返 | 初稿→一次審查→一次修正→必要定向重驗 |
| 交給 html-ppt skill | 沒有真正對交付負責的 Bot | 依內容指定 CoS／Tutor／Architect，skill 只是方法 |
| 列出文件就當成權威 | 舊副本、不可讀檔案或衝突被忽略 | 依資料欄位定來源，核對版本、用途與可讀性 |
| 「只與 CoS 說話」套用所有情境 | Tutor 即時問答變成層層轉述 | 上課直接與 Tutor 互動，CoS 收開始／結束摘要 |

review 保留了各 Bot 重複出現的核心授權與真實性規則。未要求另建工作帳本、全面擴編或增加每次工作的審查人數。

## Grok 可以讀到哪些資料

Grok 不會自動取得 Codex 的資料夾權限、聊天紀錄或本機檔案。官方將本機執行列為與雲端不同的能力；必須實際啟用，並按本機核准政策執行。[Use the computer and apps](https://docs.x.ai/grok-bot/computer-and-apps)

| 交付方式 | 可提供什麼 | 不可假設的事 |
|---|---|---|
| 上傳必要檔案 | 當次副本 | 本機後續修改會自動同步 |
| 連接正式來源 | 帳號權限內的資料 | Connector 存在就已登入或獲准寫入 |
| 授權本機能力 | 指定可存取範圍與動作 | Codex 的授權自動轉給 Grok |

建議先給更新後的 about-me.md，再按任務補核准履歷、主張與必要 tracker 摘要。`../Web3/...` 只是一個相對來源指標，上傳 about-me.md 不會連帶上傳 Web3 文件。完整私人 voice-profile 與 Codex 專用配置不預設加入團隊共用資料。

本次在 Wiki 保存資料也不等於 Grok 已經能讀 Wiki。尚未操作 Grok 帳號確認資料、Bot profile、skills、connectors 或 routines 是否存在。使用者提供「目前設定」屬使用者陳述，不能改寫成助手已登入驗證。

## 正式資料的來源分工

| 資料 | 優先來源 | 使用限制 |
|---|---|---|
| 求職方向與工作條件 | PROJECT_MEMORY 與本次明確指示 | 確認日期與維護日期分開；條件有變就重查 |
| 任職日期、正式職稱 | MASTER_CAREER_TIMELINE | 不為 JD 改造職稱與年資 |
| 可否公開、適用用途及核准措辭 | CLAIM_VERIFICATION_SHEET | 有證據仍須符合公開限制 |
| 履歷文案與選材 | PROFILE_CONTENT_SOURCE | 不超過 claim 核准範圍 |
| 數字與計算方式 | QUANTIFIED_ACHIEVEMENT_LEDGER | 不能取代公開核准 |
| 投遞、收件與招募階段 | 唯一既有私人 tracker 與實際收據 | 未查信、未有新證據不能推進階段 |
| 常掃職缺來源 | CoS 維護、實際可讀的清單 | 使用者提供的 `/workspace/hunter-resume/STANDING_SCAN_SOURCES_remote_jobs_2026-09-12.md` 未在 Grok 驗證 |

CoS 轉交副本不會提高其權威；每份副本保留原路徑／來源連結、版本日期及用途。資料衝突時指出欄位與影響，不自行採比較好看的版本。這份 Wiki 記錄來源關係，不另維護一份完整職涯事實庫或投遞帳本。
