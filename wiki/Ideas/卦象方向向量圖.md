# 卦象方向向量圖

## 一句話描述

> 我想把六爻卦象畫成「陽向上、陰向下」的方向向量圖，一眼看出上下卦的兩股力是**相向**還是**相背**，當作命理報告裡的視覺化元件。

## 為什麼想做

現有的命理報告（[[人類圖/Abao 人類圖解讀報告|人類圖解讀報告]]、四系統白話版、hd-decode 系列）走的是「白話先行」路線——把術語翻成人話。這個構想補的是另一條軸：**把結構翻成圖**。

文字說「水火既濟象徵圓滿、火水未濟象徵功虧一簣」，讀者只能記住結論。畫成方向圖就變成：

- **既濟**（上坎下離）：水在上往下、火在下往上 → 兩股力**相向對衝** → 交會
- **未濟**（上離下坎）：火在上往上、水在下往下 → 兩股力**相背分離** → 永遠差一點

這不是新解釋，是《象傳》「水火相就／相背」的標準訓詁，只是換成圖。**正因為是傳統說法，畫出來零風險**——不需要任何新宣稱就能成立。

## 大概怎麼做（不用想完整）

資料層已經現成：先天八卦本來就是二進位。

```
乾 111  兌 110  離 101  震 100
巽 011  坎 010  艮 001  坤 000
```

一個卦 = 六個 bit（下卦三 bit + 上卦三 bit）。渲染規則：

1. 每一爻畫一根色條：**陽（1）= 暖色 + 向上箭頭**、**陰（0）= 冷色 + 向下箭頭**
2. 上下卦各成一組，組內取「淨方向」（陽爻多 → 整組向上；陰爻多 → 整組向下）
3. 兩組淨方向**相向 → 標「交」**，**相背 → 標「離」**，同向 → 標「順」
4. 純 inline SVG，無外部相依（跟現有報告模板的 base64 圖騰同一套做法）

變卦、綜卦、錯卦全是位元運算，各一行：綜卦=反轉六爻順序、錯卦=六爻全部取反、變卦=指定爻位 XOR。

## 能不能接進四系統報告？——評估結果：⚠️ 有條件，但不建議直接接

**技術上可行**：`four-system-life-reading` 的 HD 段落做到 gate 層級（`references/methodology.md` 有 incarnation cross 四閘門、repeating gates、hanging gates 三種技法），而**人類圖的 64 個閘門就是易經 64 卦**，編號一一對應。閘門號 → 卦 → 二進位 → 向量圖，資料鏈完整，`life-chart-engine` 的輸出就有閘門號。報告模板（`assets/apple-report-template.html`，595 行）目前沒有任何 SVG/canvas，只有一張 base64 圖騰，加 inline SVG 不會撞到既有結構。

**但語意上有風險，而且是踩過的同一類**：人類圖的閘門意義來自 Ra Uru Hu 的 *Rave I Ching*，**刻意與傳統易經解釋分歧**。在一個 HD 閘門旁邊畫一張基於《象傳》的方向圖，等於把兩套互不相容的解釋並置——讀者會預設它們在講同一件事。

這跟 2026-07-18 那次「太陽合天王差 13 度、木土北交合但土星差 18 度」被懂占星的朋友當場揪出，是同一型失誤：**落點對、措辭錯，可信度整包掉**。懂人類圖的人會問「這張圖依據的是 Rave I Ching 還是周易？」，答不出來就傷。

### 建議的落點（按優先序）

| 方案 | 說明 | 判斷 |
|---|---|---|
| **A. 獨立六爻／易經模組** | 起卦、變卦、綜錯卦本來就需要視覺化，這裡用它零衝突、價值最高 | ✅ 首選，但目前沒有這個模組 |
| **B. 接 fate-compass / ziwei app** | 當通用視覺元件，用在真正講易經的地方 | ✅ 次選 |
| **C. 接四系統報告的 HD 段落** | 技術可行但語意有衝突風險 | ⚠️ 要接必須加**明確標註**：「本圖依《象傳》卦象方向繪製，與人類圖閘門的 Rave I Ching 釋義為兩套獨立系統，不互相佐證」——標註寫不清楚就別接 |
| **D. 當純裝飾用** | 不附任何解釋文字，只做視覺節奏 | ❌ 違反報告「每個視覺元素都要有意義」的既有調性 |

**現況結論**：構想本身可用且成本低（一個純 SVG 函式），但**四系統報告不是它的正確落點**。等有易經／六爻相關需求時再做，屆時 A 或 B 才是自然的容器。
