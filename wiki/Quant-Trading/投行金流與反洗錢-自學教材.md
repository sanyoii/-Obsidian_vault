# Part 1 — 前台：錢怎麼合法流動

## M1｜交易室的語言

### 白話

外匯報價是一種**方言**。同一句話（「歐元升值了」）在交易室裡必須立刻翻譯成「哪個幣是分母、我該打哪一邊的價、我的部位是多還是空」。這關過不了，後面全部聽不懂——因為 Sales、Trader、Trade Support、Operations 四個部門全靠這套術語溝通。

### 機制

**① base / terms currency（基準幣／報價幣）**
`EUR/USD = 1.0850` 讀作「一歐元換 1.0850 美元」。EUR 是 base，USD 是 terms。**數字上升 = base 升值。**

**② bid / offer 與「左邊出價、右邊要價」規則**
報價 `1.0848 / 1.0852`：
- 左邊 1.0848 = **bid**，做市商願意**買**base 的價
- 右邊 1.0852 = **offer**，做市商願意**賣**base 的價
- 你要買 EUR → 打 offer（付較高價）；你要賣 EUR → 打 bid。**價差永遠對做市商有利，這就是他的收入。**

**③ cross rate（交叉匯率）**
市場上沒有直接報價的幣對，用兩個對美元的匯率推出來。關鍵是分兩種情形：
- **同 terms**（兩者都是 `XXX/USD` 或都是 `USD/XXX`）→ 相除
- **不同 terms**（一個是 `XXX/USD`、另一個是 `USD/YYY`）→ 相乘

bid-offer 的組合方式兩種情形不同，這是手冊花最多篇幅的地方，也是新人最常算錯的地方。

**④ 部位方向**
「我買了 EUR/USD」= long EUR + short USD。同一筆交易同時是一個幣的多頭與另一個幣的空頭——**外匯沒有單邊部位**，這個直覺要建立起來。

### 為什麼重要

這不是背術語。**AML 分析、風險報表、交易對帳全部建立在「能正確描述一筆交易」之上。** 描述錯了，後面所有風險數字都是垃圾。M6 會看到雷曼自己的手冊怎麼強調這件事。

## M2｜Forward：不是預測，是利率差

### 白話

很多人以為「三個月後的美元遠期匯率」代表市場預測三個月後的匯率。**錯。** 它幾乎完全由兩個幣的利率差算出來——是一道套利封閉的算術題，不是一個觀點。

### 機制

**① 為什麼是利率差**
你有 100 萬美元、想三個月後換成歐元。兩條路：
- (a) 現在換成歐元，存三個月歐元利息
- (b) 存三個月美元利息，三個月後換

若兩條路結果不同，就有無風險套利。市場會把 forward rate 推到讓兩條路等值——所以 **forward rate = spot × (1+terms 利率) / (1+base 利率)**（期間換算後）。

**② forward points（遠期點數）**
Forward 與 spot 的差，用點數報。
- base 幣利率**低於** terms 幣 → forward 高於 spot → **premium**
- base 幣利率**高於** terms 幣 → forward 低於 spot → **discount**

**③ pay / earn the points**
你的交易方向決定你付出還是收到點數。這個判斷錯了，損益正負號就錯了。手冊 p.43 專講這件事。

**④ carry trade（利差交易）**
借低利率幣、買高利率幣，賺利差。**風險不在利差而在匯率**——利差年化 3% 可以被兩天的匯率波動吃掉。手冊 p.66 有一個 positive carry 的完整算例。

**⑤ odd dates（非標準到期日）**
客戶要的日期常不是標準的 1M/3M/6M，得內插。p.53 專講。

### 為什麼重要

理解 forward = 利率差 + 資金成本，你才會懂**為什麼 FX forward desk 同時是銀行的幣別資金調度中心**（M3 接著講）。也才會懂 M9 的鏡像交易為什麼要繞過外匯市場——因為一筆外匯交易會誠實地暴露「我要把大量 A 幣換成 B 幣送到海外」這個意圖。

## M3｜Swap：銀行的資金調度中樞

### 白話

FX swap = 同時做一筆即期 + 一筆反向遠期。它**不是**在賭匯率——兩邊方向相反，匯率風險互相抵銷。它的用途是**在時間軸上搬動貨幣**：我這週有多餘美元、缺歐元，下週剛好相反，用 swap 把兩個時點接起來。

### 機制

**① 結構**
近端（near leg）換一次，遠端（far leg）換回來。價格差就是 **swap points**，本質上還是利率差。

**② 為什麼它是資金調度工具**
銀行每天在幾十個幣別上都有零碎餘額（客戶交易、利息、結算的殘留）。**Forward desk 每天彙總全行貨幣餘額，用 Tomorrow/Next（T/N）swaps 把部位做平。** 這句話出自雷曼手冊本體——它揭露 forward desk 的真實職能：不只服務客戶，更是全行的幣別現金管理中心。

**③ 為什麼幾乎沒有匯率風險**
兩腿方向相反、金額相同，spot 變動對兩腿的影響互相抵銷。剩下的風險是**利率差變動**（影響 swap points）與**交割風險**。

### 為什麼重要

Swap 是銀行內部管道，外界看不見。它同時也是 M5 的 Repo 在證券世界的對應物——**兩者都是「用一筆現在 + 一筆反向未來」把流動性在時間上挪移**。抓住這個結構同型，兩個產品一起就通了。

## M4｜選擇權：交易的是變化的風險，不是一張圖

### 白話

新人最常犯的錯：**方向看對了還是虧錢。** 因為選擇權的價值不只看方向，還看波動率、剩餘時間、以及價格變動的「速度」。你買的不是一張靜態的損益圖，而是**一組會自己變化的風險因子**。

### 機制

**① 四個希臘字母（先只記這四個）**

| 字母 | 白話 | 你是買方時 |
|------|------|-----------|
| **Delta** | 標的動 1 塊，選擇權動幾塊 | 0%（深度價外）到 100%（深度價內） |
| **Gamma** | Delta 自己變動的速度 | 正的（對你有利，但要付代價） |
| **Theta** | 時間流逝每天損耗多少價值 | 負的（每天在虧） |
| **Vega** | 隱含波動率動 1%，價值動多少 | 正的（波動率跌你就虧） |

**② 你可以看對方向還是虧錢的四條路**
1. 買太貴 → 隱含波動率隨後下滑（Vega 虧）
2. 標的沒動夠快 → Theta 每天吃掉權利金
3. Gamma 讓 Delta 快速改變 → 你的避險一直落後
4. 靠近 barrier → Greeks 劇烈跳動，避險成本失控

**③ Gamma hedging（動態避險）**
你賣了一個選擇權，要避掉方向風險 → 依 Delta 買賣對應數量的現貨。但 Delta 會變（那就是 Gamma），所以你必須**反覆重新避險**。每次重新避險都有成本（買高賣低）。手冊 p.102–103 有完整的 gamma 交易與 P&L 算例，**這兩頁是全份手冊最有價值的地方**。

**④ Barrier / reverse knock-out 的兇險**
Barrier option 在價格觸及某個水位時生效或失效。**靠近 barrier 時 Delta 與 Vega 極不穩定**——標的動一點，你需要的避險量就跳一大截，reverse knock-out 尤甚。這是「理論上該避險 vs 實際上避不掉」的經典場景。

### 為什麼重要

這個模組是「風險不是一個數字，是一個會動的曲面」的第一堂課。M6 的 MPE（潛在最大曝險）概念直接建立在這個直覺上。

## M5｜Repo：真正的產品不是利率

### 白話

Repo 表面上是「借錢，拿債券當抵押」。但它的法律形式是**賣出證券 + 承諾以較高價買回**，價差就是利息。同一筆交易，借現金的一方叫 Repo，出現金的一方叫 Reverse Repo——**看你站哪一邊。**

### 機制

**① 六個真實用途**（這才是為什麼投行離不開它）

| 用途 | 說明 |
|------|------|
| 融資庫存 | Treasury／MBS／公司債的存貨要錢養 |
| **Matched book** | 同時借進借出，賺中間的融資利差 |
| 借特定券 | 為了交割空頭部位 |
| 處理 settlement fail | 上游券沒到，先借來交割 |
| 客戶短期流動性 | 服務性業務 |
| 閒置券變現金 | 資產負債表管理 |

因此 Repo Desk 同時牽動 **Trading / Treasury / Balance Sheet / Collateral / Credit / Settlement** 六個部門。它不是一張交易桌，是一個十字路口。

**② 完整生命週期（成交只是第四步）**

```
Quote → Client suitability → Legal agreement (MRA/GMRA) → Credit limit
  → Trade booking → Collateral allocation → Settlement
  → 每日 mark-to-market → Margin call → Substitution / Rollover / Close-out
```

雷曼的 Repo 手冊有一整節（第 VI 節）在教 sales 怎麼在 **Infinity** 前台系統輸入、修改、取消、rollover、close out，還有怎麼處理 collateral substitution。**這是「投行實務」與「教科書」最大的差別：教科書講到成交就結束，實務有一半的工作在成交之後。**

**③ 有抵押品 ≠ 沒有信用風險**
仍須考慮：抵押品價格波動、流動性與清算成本、對手方違約、**wrong-way risk**（對手違約時抵押品剛好也在跌）、settlement fail、法律文件與 close-out 可執行性、haircut 夠不夠。

**④ Haircut（折扣）**
借 100 萬現金要交 105 萬市值的券，5 萬就是 haircut——用來吸收抵押品價格波動。**haircut 訂得對不對，是 Repo 業務的核心風控參數。**

### 為什麼重要

**Repo 105 是雷曼倒閉的核心爭議**（Examiner Report 整個 Vol 3、336 頁在講這件事）。雷曼把 repo 交易做成會計上可認列為「賣出」的形式，暫時把資產搬出資產負債表，讓季末的槓桿數字看起來漂亮。懂了 M5 的機制，才讀得懂 Vol 3 在爭什麼。

## M6｜信用風險報表：風控其實是資料工程

### 白話

大眾以為風險管理是「聰明的模型」。雷曼自己的手冊講的完全是另一回事——**它 32 頁裡有一大半在講怎麼把資料弄對。** 因為模型再好，輸入的法律實體、抵押品、交易資料錯了，輸出的風險數字就是廢的。

### 機制

**① Entity mapping 是地基，不是行政小事**
同一個企業集團旗下可能有幾十個實體：基金、SPV、法律實體、trading account、prime brokerage account。
- **Parent / Child 關係**設錯 → 系統無法把同一集團的曝險加總 → 你以為對 A 集團只有 1 億曝險，實際上是 10 億
- **Agent / Principal 角色**設錯 → 你把風險算到中介身上，而不是真正的對手方

**這就是為什麼「新客戶建檔」是信用風險計算的地基。** M10（Troika）與 M11（太子集團）會看到犯罪組織正是攻擊這一層。

**② CCE 與 MPE 必須分清**

| | CCE（Current Credit Exposure） | MPE（Maximum Potential Exposure） |
|---|---|---|
| 問的問題 | 現在對手方欠我多少？ | 未來最壞情況可能欠我多少？ |
| 算法 | 正向市值 − 合格抵押品，考慮可執行 netting | 模擬引擎／VaR 流程跑出剩餘期限內的潛在曝險 |
| 為什麼要兩個 | 今天的 MTM 不代表風險 | 市場劇烈變動時才知道額度夠不夠 |

**③ 風險管理的日常是對帳**
每天要從 derivatives / financing & forwards / FX / collateral & margin / client master data 各系統取數，然後處理：missing trades、錯誤 account mapping、collateral 差異、異常日間變動、manual override，最後跟 general ledger 與 P&L 對帳。

**④ 報表必須產生行動，否則等於沒做**
`Daily Excess Report` 列出超過 notional 或 credit limit 的帳戶，Credit Analyst 必須四選一：
提高 limit ／ 要求補抵押品 ／ 降低或 close out 部位 ／ 暫停客戶交易。

CRO 報告則彙總：最大對手方曝險、MPE、margin call、rating downgrade、sovereign risk、settlement limit breach。

### 為什麼重要

**這是 Part 1 與 Part 2 的橋。** 後面五個洗錢案，全部是這一層失效的不同版本：
- entity mapping 錯 → 看不出同一集團（M10）
- 每個部門只看自己那段 → 沒人看到全貌（M9）
- 報表有紅旗但沒轉成行動 → 警告被吸收掉（M8）

# Part 2 — 後門：同一套管道怎麼被非法利用

> **讀法提示：** 這五個案子不是五個故事，是**五種攻擊面**。每讀一個，回頭問「這打的是 Part 1 哪個環節」。

## M7｜通匯銀行：把別人的清算權借來用（Wachovia，2010）

### 白話

毒販的難題不是缺現金，是**現金多到不能用**。一箱箱小面額美鈔既重、又沒法拿去買飛機或付跨國供應商。所以真正的工作是把實體現金變成帳戶餘額與美元電匯——而這一步必須借用一家能接入美元清算系統的大型銀行。

### 機制

**① 犯罪集團真正需要的三件事**
1. 把街頭美元放進金融體系（**placement**）
2. 切斷資金與毒品交易的痕跡（**layering**）
3. 讓錢能以電匯／支票／企業付款形式跨國自由移動（**integration**）

**② casa de cambio（換匯所）為什麼是理想轉換器**
拉美的換匯所本身是正當機構（旅客換鈔、進出口貨款、移民匯款）。但部分墨西哥換匯所功能遠超街邊找換店——**它們可以當交易經紀**：在墨西哥收下客戶資金，再指示美國銀行向第三方付款。

關鍵在**混池**：合法旅客、進出口商、移民匯款、販毒所得可以在同一個資金池裡混合。錢從換匯所帳戶匯出時，銀行看到的客戶**不是毒販，而是一家持牌金融機構**——原始資金的主人被藏在換匯所後面。

**③ 通匯銀行提供的四種服務（單獨都正當，組合起來是完整工具包）**

| 服務 | 內容 |
|------|------|
| 美元電匯 | 指示銀行把資金匯給全球任何人 |
| **Bulk cash** | 大宗現金：裝甲車把實體鈔票運進美國存入帳戶 |
| **Pouch deposit** | 支票、旅行支票集中裝袋送銀行處理 |
| **Remote deposit capture** | 在墨西哥掃描支票影像，經系統存入美國帳戶 |

**④ 資金鏈五步**
毒品在美國零售（收小面額美鈔）→ 現金反向偷運回墨西哥（因為美國對大額現金存款申報嚴）→ 存入 casa de cambio → 換匯所透過通匯關係送進美國銀行 → 變成飛機、商品、海外資產

### 規模與後果

美國司法部 2010 年揭露：Wachovia 數年間未能有效監控**超過 4,200 億美元**來自墨西哥換匯所的交易。

### 攻擊的是 Part 1 哪一環

**M6 的 entity/客戶識別層。** 銀行的客戶是「換匯所」這個法律實體，但真正的資金主人在它後面一層。KYC 做到了直接客戶，沒做到**實益擁有人（beneficial owner）**。

### 自測

1. 為什麼毒販要把現金**運出**美國再繞回來，而不是直接存美國銀行？
2. casa de cambio 的「混池」效果為什麼讓銀行的監控失效？
3. 四種通匯服務裡，哪一種最不需要實體移動現金？它的風險在哪？

## M8｜非居民組合：分行套利與信任鏈斷點（Danske 愛沙尼亞，2007–2015）

### 白話

一家位於愛沙尼亞、只有幾千名高風險海外客戶的小分行，八年間有約 **2,000 億歐元**資金進出。監管機關、代理銀行、內部吹哨者輪流發出警告——但這項業務太賺錢了。

### 機制

**① 這批客戶為什麼要愛沙尼亞**
- 地理與語言接近俄羅斯，**且已在歐盟**（2011 年起用歐元）
- 銀行系統能接上西歐與美元清算網絡
- 分行熟悉前蘇聯客戶，開戶方便

錢從俄羅斯進愛沙尼亞後，**不再是俄羅斯銀行匯出的盧布，而是一家丹麥大型銀行的歐盟分行、透過西方代理銀行發出的美元。** 身分洗白發生在這一步，不在後面。

**② 空殼包裝**
許多客戶用英國、英屬維京群島公司開戶——沒有員工、沒有辦公室、申報收入是零，帳戶裡卻轉進數千萬美元。**英國公司給了「西方企業外觀」。**

**③ 這套系統為什麼會獎勵視而不見**

| 設計 | 後果 |
|------|------|
| 利潤留在分行，風險分散給總行與代理銀行 | 賺錢的人不承擔風險 |
| 客戶資料在當地，美元清算依賴其他銀行 | 有資料的人不清算，清算的人沒資料 |
| 管理層看財務成績，看不到底層交易 | 好消息傳上去，壞消息留在下面 |
| 合規警告沒有直接否決業務的權力 | 紅旗被吸收，不變成行動 |

### 規模與後果

2007–2016 相關美元帳戶為非居民客戶處理約 **1,600 億美元**交易。2022 年 Danske Bank 在美國承認串謀銀行詐欺，同意跨國和解約 **20 億美元**；SEC 另就誤導投資人與未充分揭露 AML 風險提出詐欺指控。

### 攻擊的是 Part 1 哪一環

**M6 的「報表必須產生行動」層。** 異常不是沒被看見——是被看見了、被報告了，然後**因為合規沒有否決權而被吸收掉**。

> **最該記住的一句：** 全球美元系統靠層層信任運作，當每一層都相信上一層已經審查過，源頭出事時就沒有一層知道。

## M9｜鏡像交易：拆成兩筆正常交易（德意志銀行，2011–2015）

### 白話

一名俄羅斯客戶在莫斯科用盧布買進一億美元的俄羅斯藍籌股；**幾乎同時**，另一家由他控制的離岸公司在倫敦賣出完全相同的股票，收取美元匯進塞浦路斯。他不看多也不看空，甚至不在乎股價——**股票只是讓盧布合法穿過國境的遮羞布。**

### 機制

**① 為什麼不直接換匯**
一筆外匯交易會誠實地告訴銀行：「我想把大量盧布換成美元並移到海外。」鏡像交易把同一件事拆成兩筆看似正常的股票買賣：
- 只看莫斯科的人：客戶在買股票
- 只看倫敦帳簿的人：另一個客戶在賣股票
- 支付與清算部門：證券交易產生的正常款項

**只有把客戶關係、實益擁有人、下單時間、股票名稱、數量、幣別、最終收款帳戶全部疊起來看，圖案才會浮現。**

**② 最關鍵的漏洞：Remote booking**
倫敦端部分交易不是倫敦交易員接單，而是莫斯科前台透過 remote booking 直接記進德銀英國帳簿。這種安排在跨國投行不罕見（集中風險、資本、流動性管理），但它創造了**責任真空**：

| 誰 | 怎麼想 |
|----|--------|
| 莫斯科 | 客戶是我介紹的，但交易記在倫敦 |
| 倫敦 | 交易是莫斯科執行的，KYC 靠當地 |
| 合規 | 我看到的是個別交易，不是跨地區組合 |
| 支付 | 這是正常證券交割款 |

FCA 後來發現，**德銀英國前台甚至不知道自己才是這些客戶 KYC 責任的最終承擔者。**

**③ 紅旗清單（多到幾乎不可能忽視）**
- 兩家關聯公司同時買賣相同證券，數量與價值高度一致
- 客戶反覆進行幾乎不承擔市場風險的交易
- 海外公司缺乏清楚的商業活動
- 交易量與客戶申報財力不相稱
- 資金流向塞浦路斯、愛沙尼亞、拉脫維亞
- 下單人可能代表銀行不知身分的第三方

> **判準：** 正常投資人買股票是因為期待上漲。**當一個客戶不在乎報酬、只在乎用哪種貨幣在哪個國家收到錢，他買的就不是股票。**

### 規模與後果

2012-04 至 2014-10 處理超過 **2,400 組**鏡像交易、移出逾 **60 億美元**；另發現約 38 億美元可疑單邊交易，監管估整體接近 **100 億美元**。
2017 年 FCA 罰約 **1.63 億英鎊**（當時 FCA 反洗錢處分紀錄）；紐約州金融服務署另罰 **4.25 億美元**並要求聘獨立監察人。

FCA 未認定德銀英國高層知情參與，判定 AML 缺失屬**疏忽**而非蓄意；NYDFS 措辭更嚴厲，認為全球性內控缺陷讓交易員與離岸實體得以濫用德銀莫斯科／倫敦／紐約業務。

### 攻擊的是 Part 1 哪一環

**M1 的「能正確描述一筆交易」層 + M6 的彙總層。** 每一筆單獨看都描述正確、都正常。錯的是**沒有任何一個視角能同時看到兩筆**。

> **這個案子最重要的結論：** 洗錢不需要整家銀行共謀。只需要交易員覺得那是合規的事、合規覺得那是前台的責任、倫敦以為莫斯科查過、管理層只看到收入沒看到交易。

### 自測

1. 鏡像交易為什麼比直接換匯「安全」？它規避的是什麼？
2. Remote booking 的正當用途是什麼？它為什麼同時製造責任真空？
3. 列出三個能單獨識別鏡像交易的紅旗。
4. 要偵測這種模式，監控系統必須把哪些欄位放在一起看？

## M10｜平行金融系統：自建一整套（Troika Laundromat，2006–2013）

### 白話

前三個案子是**利用**西方銀行的漏洞。Troika 不同——它被指建立了一整套由離岸公司、代理董事、虛假合約與銀行帳戶構成的**平行金融網絡**。至少 75 家離岸公司。它同時是地下匯款系統、隱藏投資工具、秘密共同基金、避稅架構與富豪私人金庫。

### 機制：四道工序

**第一步 — 創造一群不存在的商人**
2006 至 2013 年初使用至少 75 家離岸公司，多設於英屬維京群島等地。紙面上的董事、股東、授權簽字人可能只是普通工人或經濟困難者（例如一名亞美尼亞裝修工人的姓名與護照出現在空殼公司文件上，他表示從未見過這些文件）。

**這些人提供的不是管理能力，是一層法律距離。** 調查人員追到的第一個名字是裝修工、代理董事或註冊服務商，而不是實際控制資金的人。

**第二步 — 建立公司家族樹**
75 家不是各自獨立。三家 BVI 核心公司（Quantus、Gotland、Reformation）被用來建立或控制更多離岸實體。公司彼此借款、買賣、轉帳，再與網絡外的客戶公司連接。

**真正的客戶不必直接把錢匯給最終收款人**——他把錢交給網絡中的一家公司，系統從另一家公司的帳戶替他付款。**進去的錢與出去的錢不需要是同一筆**，這是它比普通空殼公司高明的地方。

**第三步 — 把所有人的錢混在一起（layering）**
客戶 A 要把一千萬移出俄羅斯、客戶 B 要在倫敦買房、客戶 C 要付孩子英國學費，另一筆可能來自詐欺。系統把資金匯入多個空殼帳戶、反覆內部交易、再從不同節點支付。

**目的不是讓錢多繞幾圈，而是打斷來源與去向的直接關係。** 警方追客戶 B 的房款，看到的是某家離岸貿易公司；追那家公司，錢來自另外三家；每家又與數十個對手往來，而不同客戶的資金早已混合。

OCCRP 估計：約 **46 億美元流入**、**48 億美元流出**；網絡內部公司彼此另產生約 **88 億美元**交易。**那 88 億不是新資金，是同一批錢在網絡內反覆流轉的交易量——轉越多次，原始來源越難辨認。**

**第四步 — 替每筆錢寫一個故事**
銀行不能憑「幫某位富豪把錢搬出去」完成匯款，所以每筆交易都需要商業理由。網絡產生大量合約、發票與交易描述：食品、金屬、汽車零件、電腦、一般商品、顧問服務、貸款、股票買賣、**合約取消費**。

問題是同一家公司這一刻買電腦、下一刻賣食品、接著交易金屬，沒有員工、倉庫、網站或真實營運證據，帳戶裡卻有上千萬美元流動。

> **核心技術：** 錢不能沒有故事。**故事不必合理到能說服偵探，只要合理到足以讓銀行職員按下「批准」。**

**最荒謬的產品：合約取消費**
兩家公司簽署交易合約，其中一方不久取消，依約支付巨額違約金。表面上收款人只是收到合法賠償，實際上原本可能根本沒打算完成交易。（報導指一名與俄羅斯政界關係密切的大提琴家相關公司曾簽 16 份很快取消的合約、取得約 1,160 萬美元取消費；OCCRP 追蹤到與其相關公司至少從網絡收到 6,900 萬美元。當事人未回應提問。）

### 攻擊的是 Part 1 哪一環

**M6 的 Parent/Child + Agent/Principal 層，正面攻擊。** 這整套系統的設計目的就是讓 entity mapping 不可能做對——因為紙面上的所有關係都是假的。

### 自測

1. Troika 與前三個案子的根本差異是什麼？
2. 「進去的錢與出去的錢不需要是同一筆」為什麼是關鍵設計？
3. 46 億流入、48 億流出，但內部交易 88 億——這 88 億代表什麼？
4. 為什麼「假合約」這一步不可省略？它服務的對象是誰？
5. 「合約取消費」為什麼特別好用？

## M11｜從實體園區到鏈上：詐騙經濟的金流（太子集團／匯旺／Lazarus）

### 白話

前四個案子的錢，最後都要回到現實世界（銀行存款、房產、公司股權）。所以政府至少找得到一個人、一幢可查封的房子、一家可清算的銀行。**這個模組的下半段講一種新東西：一條幾乎完全平行於銀行體系、能自動運作、不需要任何人批准的資金通道。**

### Part A — 太子集團：實體版（第一哩到最後一哩）

**第一哩：人頭帳戶與跑分**
台灣受害者被說服投資，對方給的**不是**柬埔寨帳戶，而是台灣本地個人或公司帳戶。帳戶持有人可能主動出售帳戶，也可能以為自己在做代購、電商、換匯或居家收付款。

資金進入後立即被拆散，轉入更多帳戶、電子錢包、支付工具——這叫**跑分**，按經手金額給帳戶提供者佣金。AML 術語裡這是 **layering + structuring**。

> **關鍵判準（面試常問）：** structuring 不是「每筆都剛好卡在申報門檻以下」。真正的 red flag 是**交易行為與客戶背景嚴重不符**——例如一個沒有固定收入的學生帳戶，數小時內收到數十名陌生人匯款，又立刻全部轉走。

**銀行的困難不是看不到異常，而是要在數百萬筆正常交易中判斷哪些碎片來自同一個犯罪網絡。** 警方向第一家銀行取證時，錢可能已經過十幾個帳戶、進了另一家銀行、換成了加密貨幣。

**第二哩：為什麼是 USDT**
場外交易商接受銀行存款或現金，向園區指定錢包支付等值 USDT。穩定幣的優勢：美元計價、全天候、跨境即時結算，不必在每個國家開銀行帳戶。

**但「變成 USDT 就追不到」是錯的。** 銀行交易私密但有實名；公鏈交易公開但以地址呈現。調查者看得見資金從一個錢包到另一個錢包，卻不一定知道地址背後是園區、場外商、交易所客戶還是人頭錢包。

鏈上手法：**spraying**（分散到數十個地址）與 **funneling**（多次轉帳後重新集中）。目的不是讓錢消失，是切斷資金與原始犯罪最直觀的關聯。

**這與傳統地下錢莊原理完全相同：**
台北有人要把台幣換成倫敦的英鎊 → 把台幣交給台北的地下匯兌商 → 對方通知倫敦夥伴支付英鎊。台幣沒離開台灣，英鎊沒進入台灣，監管者只看到兩筆互不相干的境內交易。
**地下銀行跨境移動的不是錢，是債權。** 兩地中介商日後用反向客戶需求、貿易貨款、現金、博彩籌碼或加密貨幣軋差。現代版唯一的升級：把私人帳本上的欠款換成幾分鐘內可全球移轉的 USDT。

**平台化：匯旺（Huione）**
匯旺不是太子集團旗下企業，兩者是同一生態的不同角色：**太子生產詐騙收益，匯旺提供支付、換匯與洗錢工具的金融基礎設施。** 旗下含支付機構、虛擬資產服務商，以及一個運作像電商平台的線上市場（商戶繳保證金入駐、平台擔保交易處理爭議收費）——差別在販售的是人頭帳戶、洗錢通道、網站基礎設施等工具。

FinCEN 認定其在 2021-08 至 2025-01 間至少清洗 **40 億美元**非法所得（含北韓網路竊案、虛擬貨幣投資詐騙）。2025-10-14 動用《愛國者法案》第 311 條把匯旺切出美國金融系統——**與美英制裁太子集團、公開起訴書同一天。**

> **打擊邏輯（值得記）：** 一邊處理生產詐騙收益的集團，另一邊切斷替整個產業搬運資金的地下金融平台。只抓園區裡聊天的人幾乎沒有意義——他們可能是被迫工作的受害者，也能在幾天內被取代。**難以替換的是收款網絡、場外商、技術平台，以及能承擔資金凍結風險的專業洗錢者。**

**最後一哩：integration**
傳統三段論 placement → layering → integration，園區收款與跑分屬前兩步。太子集團值得注意的是**它如何完成第三步**：利用專業洗錢網絡、自己控制的線上博彩與加密貨幣挖礦業務清洗收益，部分資金進入交易所、銀行帳戶與未託管錢包，另一些買遊艇、私人飛機、度假住宅、名錶、藝術品。

> **這裡有個反直覺的重點：** 洗錢不總是把髒錢藏進合法企業——**有時髒錢本身就是企業擴張的資本。** 當詐騙收益用來買地、建酒店、成立銀行、投資航空，非法資金就不再只是藏在帳戶裡，而是變成能創造租金、就業、稅收與政治影響力的實體經濟。房地產儲值又能透過複雜架構隱藏受益人；酒店娛樂有大量難核實的客流與現金；銀行與支付公司提供帳戶、匯款與資金池。**當集團同時控制產生贓款的園區、搬運資金的通道與接收資金的合法企業，洗錢就從外包服務變成企業內部流程。**

**規模：** 起訴書指集團自約 2015 年建立、企業遍及 30 多國；財政部指其網絡使用超過 100 家空殼及控股公司，並制裁 117 家相關企業（多數被認定無明顯實質商業活動）。美方對 **127,271 枚比特幣**提出民事沒收。台灣刑事局 2025-11 表示集團在台設有公司與疑似洗錢據點，法院批准扣押不動產、車輛及帳戶，估值合計約新台幣 45.3 億元；新加坡警方至 2026-06 已查扣或限制處分超過 6 億新加坡元資產。

**注意：起訴不等於定罪，比特幣走的是民事沒收程序。**

### Part B — Lazarus / Bybit：鏈上版（2025-02）

**攻擊手法：改掉簽署者看到的世界**
Bybit 冷錢包用多重簽章。攻擊者**沒有破解私鑰**——入侵前端系統、在網頁介面植入惡意 JavaScript。簽署者螢幕上顯示的是普通轉帳，實際簽署的是修改錢包控制權限的交易。**簽名是真的、私鑰沒被盜、授權全數通過，唯一被動過手腳的是簽署者眼前看到的內容。**

這是**盲簽風險**：你以為簽的是一份文件，實際是另一份。調查另發現攻擊者曾盜用 session token 進入雲端環境、試圖註冊假的多因素驗證裝置——結合供應鏈污染、雲端憑證竊取與介面操縱。

**入口通常是一封普通的 email。** 高度客製化的魚叉式釣魚：研究目標職位、工作內容、社交圈、職業興趣，偽裝成獵頭、客戶、會議主辦人或同行。工程師在職涯社群收到高薪機會，聊過幾輪後對方傳來一份「需要下載執行的技術測驗」。

> **對 QA／安全背景的人最該記的一句：** 你可以買最好的硬體、最貴的監控與最嚴格的權限管理，但很難防住一個疲憊的人在某個下午順手點開一個檔案。

**贓款去哪：chain-hopping**
約 40 萬枚 ETH、約 15 億美元。區塊鏈公開，資金留在原以太坊地址就會被全球看見，所以必須快：換成比特幣與其他資產、分散到不同鏈上的數千個地址，最後換成超過一萬枚 BTC 散落數千個錢包。

**關鍵動作是把 ETH 換成 BTC。** 以太坊生態透明、相關錢包已被標記，資金留在上面就像提著噴了螢光漆的行李箱走機場。使用的工具之一是去中心化跨鏈交換協議——**不需要傳統中間人，沒有一名 compliance 可以接電話，也不存在客服中心能按下「凍結」。**

**chain-hopping 不會抹掉紀錄，但會讓追蹤支離破碎。** 每條鏈有不同資料結構、地址格式、交易邏輯與分析工具，資金每跨一條鏈，調查人員就得重新拼接一次身分與控制權。

**「追得到」不等於「追得回」**
案發後鏈上分析師極短時間內鎖定攻擊者、重建大部分資金流向、通報全球交易所。但：
- 你看見贓款進入某地址 ≠ 你有權凍結它
- 你通知一家交易所 ≠ 該司法管轄區願意理會
- 你發出制裁名單 ≠ 你能要求一段去中心化程式碼交出客戶資料

**只要最後一哩的 off-ramp 落在不配合制裁、監管薄弱、甚至本身依賴地下金融的地方，凍結令可能只是一張寄不到收件人手中的公文。**

**執法市場化（新現象）**
Bybit 推出賞金平台：追蹤贓款並提供有效證據、最終協助凍結者分 5%，實際執行凍結的交易所／機構再取 5%——每追回 100 美元拿出 10 美元。同時發布可疑錢包黑名單 API 供交易所與研究者即時取用，並設排行榜公開表揚配合者、點名拒絕配合者。

**為什麼這是國家行為**
Lazarus 被普遍認為隸屬北韓情報機構。對一個被制裁、外匯來源極度有限的政權，這些錢不是買豪宅跑車，而可能用於維持軍事工業、採購受管制零件。**當一個國家發現派駭客偷加密貨幣比出口煤礦、賣武器或派遣海外勞工更快更便宜且更難攔截，加密貨幣就從投機資產變成被制裁政權的外匯儲備。**

### 這改寫了 AML 的防守假設

| | 傳統 AML | 鏈上版本 |
|---|---|---|
| 核心假設 | 犯罪分子最後總有一刻要進入某家銀行／支付公司／受監管交易所 | 大部分路徑可以留在銀行體系之外 |
| 防守點 | KYC、交易監控、可疑交易報告、資產凍結 | 只剩 off-ramp 那一哩 |
| 可追責主體 | 有一個人、一幢房、一家公司 | 可能只有一段部署好的智能合約 |

被制裁的混幣協議是最典型的例子：它不是傳統公司，核心功能由鏈上智能合約執行。**前端網站可以被封鎖、開發者可以被起訴、地址可以被列入制裁名單，但已經存在於鏈上的程式碼不會因為收到法院命令就停止運作。你可以制裁一家公司、逮捕一名董事、拔掉一台伺服器，卻很難逮捕一段程式碼。**

# Part 3 — 貫穿主線

## M12｜五個案子，同一個失效模式

### 一句話

**沒有一個案子是「異常沒被看見」。全部都是「異常被看見了，但沒有任何一層擁有整個問題」。**

### 五案對照

| 案例 | 被濫用的正當機制 | 失效的那一層 | 一句話診斷 |
|------|----------------|-------------|-----------|
| Wachovia | 通匯銀行服務（電匯／bulk cash／pouch／RDC） | 實益擁有人識別 | 客戶是持牌換匯所，真正的人在它後面 |
| Danske | 分行的非居民業務 + 代理銀行清算 | 合規的否決權 | 紅旗有被報告，但合規不能停業務 |
| 德意志銀行 | Remote booking（集中風險管理） | 跨地區彙總 | 每筆單看都正常，沒人能同時看兩筆 |
| Troika | 離岸公司與貿易融資文件 | Entity mapping | 紙面上的所有關係都是假的 |
| 太子／Lazarus | 支付機構、穩定幣、跨鏈協議 | 最後一哩的司法管轄 | 追得到不等於追得回 |

### 四個可遷移的判準

**① 沒有經濟目的的交易 = 最強紅旗**
反覆支付價差與手續費、只為同時完成兩筆相反交易；反覆簽約又取消只為收違約金；不承擔市場風險卻大量交易。
**問法：這筆交易在經濟上到底為了什麼？** 比「文件是否齊全」有用一百倍。

**② 行為與背景不符 > 金額門檻**
學生帳戶數小時內收數十筆陌生匯款；申報零收入的空殼公司帳上流過數千萬；交易量與客戶財力不相稱。
**門檻是死的，行為畫像是活的。**

**③ 責任真空比惡意更常見**
洗錢通常不需要整家銀行共謀，只需要每一層都少問一個問題：前台覺得那是合規的事、合規覺得那是前台的責任、A 地以為 B 地查過、管理層只看到收入。
**找責任真空：哪個環節「所有人都以為別人在管」。**

**④ 資料品質就是風控上限**
Entity mapping 錯 → 曝險加總錯 → 風險數字無意義。這句話在雷曼自己的手冊裡，也在每一個洗錢案裡。

### 手冊 × 證物對讀法（一手材料的最高用法）

Examiner Report 九冊共 **4,105 頁**，含 8,000+ 條註腳，且註腳連到被引用的原始文件（內部郵件、簡報、政策、管理層往來）。

| 手冊告訴你 | 證物告訴你 |
|---|---|
| 流程理論上如何運作 | 員工實際上如何處理 |
| Limit 與 control 如何設計 | Limit 是否被繞過或延後 |
| 問題應該如何升級 | 壞消息是否真的傳到管理層 |
| Repo 如何管理抵押品 | 資產負債表壓力如何影響決策 |
| Risk report 如何製作 | 管理層如何解讀或忽略報告 |

**做法：** 先讀手冊建立「應有流程」基準線 → 再沿註腳追實際如何偏離。**不要逐封郵件亂看。**

**建議切入點：** Vol 1（Risk，239 頁）對讀 CRR 手冊；Vol 3（Repo 105，336 頁）對讀 Repo 手冊。

# Part 4 — 應用

## M13｜傳統概念 → Web3/CEX 面試語言

### 為什麼這份教材對 CEX／託管職位有用

CEX 合規與託管崗位的面試語言，**幾乎全部是傳統金融概念的重新命名**。你懂了 Part 1+2，就懂了他們在問什麼。

| 傳統概念（本教材） | CEX／託管的對應問題 |
|---|---|
| M1 正確描述一筆交易 | 鏈上交易的 attribution：地址背後是誰？交易所熱錢包、用戶、還是 OTC 商？ |
| M4 Greeks／動態避險 | 永續合約資金費率、槓桿代幣的再平衡、清算引擎 |
| M5 Repo haircut 與 margin call | 借貸平台的抵押率、清算線、連環清算風險 |
| M6 CCE / MPE | 交易所對用戶的潛在曝險；保險基金該備多少 |
| M6 Parent/Child entity mapping | **地址簇（address clustering）**：哪些地址屬於同一實體 |
| M6 Daily Excess Report → 行動 | 風控告警 → 凍結／限制提幣／要求補倉，誰有權按下按鈕 |
| M7 實益擁有人 | KYC／KYB 穿透；VASP 的最終受益人 |
| M8 代理銀行信任鏈 | **VASP-to-VASP 轉帳與 Travel Rule**：對方交易所的 KYC 你信不信 |
| M9 跨地區彙總失效 | 多鏈、多交易所、多法人的統一監控 |
| M10 layering 與假商業理由 | 混幣器、spraying/funneling、鏈上「交易理由」的無意義性 |
| M11 最後一哩 off-ramp | 提幣風控、制裁名單比對、不配合管轄區的處理 |
| M11 盲簽風險 | **託管簽核流程的介面完整性** ← QA 背景的直接切入點 |

### 兩個對 QA 背景特別有利的切入角

**① 盲簽 = 介面與實際行為不一致**
Bybit 案的本質是「顯示的內容 ≠ 簽署的內容」。這是 QA 的母題：**UI 呈現與底層狀態的一致性驗證。** 託管簽核流程要防這個，需要的正是：獨立通道驗證交易內容、簽署前的 out-of-band 確認、對前端資產完整性的持續檢核。這條路你講得比純金融背景的人具體。

**② 提幣狀態機**
提幣流程是一個典型狀態機：申請 → 風控檢查 → 制裁比對 → 額度檢查 → 多簽 → 廣播 → 確認 → 完成，任何一步可以退回、可以卡住、可以被人工介入。**狀態機的邊界條件、非法轉換、並發衝突、重放——全部是 QA 的專業區。**
