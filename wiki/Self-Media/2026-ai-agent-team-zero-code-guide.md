## 核心概念

### 為什麼要用 Agent

**傳統方式 vs Agent 方式**

| 方式 | 特徵 | 槓桿 |
|------|------|------|
| **聊天機器人** | 逐步指引：「去這個網站」→「輸入這個」→「點那個按鈕」 | 你在做管理員的工作 |
| **AI Agent** | 高層指令：「幫我預訂機票」 | Agent 自行分解步驟、自動執行 |

核心差異在於**委託 vs 親力親為**。Agent 能理解你的目標，自行規劃並完成工作流。

**市場價值**
- 企業正在招聘具備 Agent 建置能力的人
- 自由工作者正在以此高價收費
- 創辦人正以此建立完整產品線
- 進入門檻比大多數人想像的要低

## Module 1：AI Agent 的四個組件

每一個 AI Agent，無論多複雜，都由這四項組成：

### 1. 角色（Role）

Agent 的職位定義。不是泛泛地「做東西的 AI」，而是**一個特定工作的專家**。

**例子：**
- 研究 Agent：搜尋並整理特定主題的信息
- 寫作 Agent：把大綱轉化成完整文章
- 分析 Agent：處理數據、發現模式
- 編輯 Agent：審視內容並提升品質

角色越具體，Agent 表現就越好。

### 2. 指令（Instructions）

定義 Agent **如何**完成工作。不只是「研究」，而是**詳細的流程和品質標準**。

**好的指令範例：**
> 「針對你獲得的每個研究主題，進行以下操作：
> 1. 尋找 5 個最重要的子主題
> 2. 針對每個子主題蒐集關鍵事實、統計數據和專家觀點
> 3. 識別該主題內任何矛盾或爭議
> 4. 在結構化文檔中彙總發現
> 5. 在結尾加入「要點提示」區段（3-5 個可行動的洞察）」

指令定義了流程、質量標準和輸出格式。

### 3. 工具（Tools）

Agent 可以在現實世界中做什麼。

**可用工具示例：**
- 網路搜尋（瀏覽網頁）
- 文件存取（讀寫你的檔案）
- Email 整合（收發郵件）
- 日曆連接（查看你的時間表）
- Slack 或其他應用整合

工具決定了 Agent 的「能力邊界」——它能在現實中實際執行什麼。

### 4. 記憶（Memory）

Agent 如何記住工作成果。

**記憶的作用：**
- 能參考過去的工作成果嗎？
- 知道你的工作偏好嗎？
- 上次的反饋會改進這次的輸出嗎？

記憶是讓 Agent 從「一次性工具」升級為「持續助手」的關鍵。

## Module 2：建立你的第一個 Agent（五個步驟）

### 第一步：定義角色

選擇一個能替你省時間的工作。這些是常見的起點：

| 角色 | 功能 | 適用情景 |
|------|------|---------|
| **內容研究 Agent** | 搜尋並總結任何主題 | 需要蒐集背景資料 |
| **初稿 Agent** | 把你的想法轉成文稿 | 有大綱但不想親自寫 |
| **數據整理 Agent** | 整理檔案、提取信息 | 大量手工資料處理 |
| **會議準備 Agent** | 事前研究人物和主題 | 要參加重要會議 |
| **週報 Agent** | 編譯你的數據成格式化報告 | 定期彙總工作成果 |

在本指南中，我們以**內容研究 Agent** 為例。

### 第二步：撰寫系統指令

在 Cowork 中開啟新 Session，輸入這些指令給 Claude：

```
你是我的內容研究 Agent。
你的工作是研究我給你的任何主題，並產出結構化研究簡報。

針對每個研究任務，執行：
1. 識別 5 個最重要的子主題
2. 針對每個子主題，找出關鍵事實、統計數據和專家觀點
3. 識別該主題內任何矛盾或爭議
4. 把發現彙總在結構化文檔中
5. 在結尾加上「核心要點」區段（3-5 個可行動的洞察）

輸出格式：存成 [主題名稱]-research.md 到我的 /Research 資料夾

品質標準：每個宣稱必須具體。不要模糊其詞。如果找不到可靠信息，就直說，不要瞎編。

語氣：專業但易懂。以聰慧但非本領域專家的人為目標讀者。
```

### 第三步：給它存取權限

授權 Cowork 存取你希望 Agent 保存工作的資料夾。建立 `/Research` 資料夾（如果沒有的話）。

如果你已設置連接器（Gmail、Google Drive、Slack），Agent 也能從那些來源提取信息。

### 第四步：測試它

給它第一個任務：

> 「研究目前商業界 AI Agent 的發展狀況。重點放在公司實際在用的東西，而不是理論假想。」

觀察它工作。它會規劃方法、執行研究，並把格式化文檔自動存到你的 Research 資料夾。

### 第五步：優化

第一個輸出會不錯，但不完美。這是正常的。檢視它，告訴 Claude 改進方向：

> 「段落太長了。把每個子主題的摘要控制在 100 字以內。」

> 「在最上面加一個段落的行政摘要。」

> 「我想看你給每個來源一個 1-5 的可信度評分。」

每個改進都讓 Agent 在下一次做得更好。

**恭喜！你剛建立了一個 AI Agent，沒寫一行程式碼。**

## Module 3：建立 Agent 團隊

一個 Agent 很有用。一個團隊則是革命性的。

以下是一個完整工作流的例子，其中每個 Agent 執行不同的角色，互相協作完成內容的全流程。

### 內容製作團隊（4 個 Agent）

#### Agent 1：研究 Agent
你已經建立過了。它搜尋並整理任何主題的信息。

#### Agent 2：大綱 Agent

```
你是我的內容大綱 Agent。
你的工作是把研究簡報轉化為詳細的內容大綱。

流程：
1. 完整讀過研究簡報
2. 確定對目標觀眾最有力的切入角度
3. 撰寫標題（必須含具體數字和吸引力鉤子）
4. 構建分段式大綱，每段包含：
   - 分段標題
   - 關鍵要點（每段 3-5 個）
   - 具體例子或數據點
   - 預估字數
5. 撰寫開場段（吸睛的鉤子）
6. 撰寫結尾段（行動呼籲）

存成 [主題名稱]-outline.md 到我的 /Outlines 資料夾。

大綱必須詳細到別人能看著它寫完整文章，不需要提問。
```

#### Agent 3：寫作 Agent

```
你是我的內容寫手 Agent。
你的工作是把大綱轉化為完整、拋光的文章。

流程：
1. 寫文章前完整讀過大綱
2. 按大綱結構精確寫作
3. 使用短段落——最多 3 句
4. 用粗體突顯關鍵短語，便於掃讀
5. 納入大綱中的所有具體數字和例子
6. 全文保持語氣一致

風格：直接、對話式、零廢話。像在跟聰慧的朋友說話，不是在講課。

不要寫成：通用 AI 文風、企業部落格、LinkedIn 影響力風格、學術論文。

存成 [主題名稱]-draft.md 到我的 /Drafts 資料夾。
```

#### Agent 4：編輯 Agent

```
你是我的內容編輯 Agent。
你的工作是把初稿改進到出版品質。

流程：
1. 先讀完整份初稿
2. 檢查：事實準確度、邏輯流暢、語氣一致、冗餘內容
3. 改進：平淡的開場、模糊的表述、缺失的過渡、虎尾的結尾
4. 強制執行：短段落、粗體關鍵詞、具體數字優於模糊宣稱
5. 刪除：任何不增加價值的句子
6. 產出最終拋光版本

品質檢查清單：
- 開場在前 2 行就能抓住注意力嗎？
- 每一段都履行了它的標題承諾嗎？
- 我會分享這個嗎？我會存檔嗎？
- 行動呼籲清楚又有說服力嗎？

存成 [主題名稱]-final.md 到我的 /Published 資料夾。
```

### 執行工作流

**流程如下：**

1. 告訴研究 Agent：「研究 [主題]」
2. 把它的輸出交給大綱 Agent：「根據這份研究簡報建大綱」
3. 把大綱交給寫手 Agent：「根據這份大綱寫完整文章」
4. 把初稿交給編輯 Agent：「編輯到出版品質」

**結果：** 從原始主題到已發表的文章，耗時不到 30 分鐘。零人工寫作。

## Module 4：進階技巧

一旦你的基礎團隊運作順暢，這些技巧能大幅提升效能。

### 技巧 1：排程 Agent 工作流

使用 Cowork 的 `/schedule` 在計時器上自動化你的 Agent。

**例子：**
- 每週一上午 7 點：研究 Agent 拉取你領域內的趨勢主題並存簡報
- 每週一上午 8 點：大綱 Agent 為前 3 個主題建大綱
- 你檢視大綱，挑出最好的，讓寫手 Agent 製作它

**結果：** 你的內容管線在自動駕駛，你專注策略。

### 技巧 2：Context 一致性檔案

建立一個 `context.md` 檔案，所有 Agent 工作前都讀它：

```markdown
# 我的內容背景

目標觀眾：25-40 歲的科技精英，用 AI 工具建東西

領域：AI 生產力、Claude 生態、自動化工作流

語氣：直接、零廢話、稍微不正經

永不用：「在快速變化的時代」、「槓桿」、「釋放」、「改變遊戲規則」

永遠用：具體數字、可行動的步驟、真實例子

格式：短段落、粗體關鍵詞、清晰的分段
```

在所有 Agent 的指令中加上：「開始任何工作前讀 context.md」。這確保你整個團隊風格一致。

### 技巧 3：回饋迴圈

在每個主要輸出後給 Agent 具體反饋：

> 「研究簡報不錯，但理論太多。下次優先用實務例子和案例研究，少用定義。」

> 「初稿強，但結尾弱。一定要以對比作結：讀者什麼都不做會怎樣 vs 他們採取行動會怎樣。」

每條反饋都讓未來的輸出更好。一段時間後，你的 Agent 會學到你的標準，不用你重複指令。

### 技巧 4：多步驟自動工作流

在 Cowork 中，你能把多個 Agent 串成一個工作流：

> 「以『小企業的 AI Agent』為主題，跑完整管線：研究 → 大綱 → 寫作 → 編輯。存所有中間檔案。把最終文章交給 /Published。」

Claude 全程自動化處理。你回頭時已有一篇完整文章。

## Module 5：Agent 團隊範本

以下是三個你可以立即建立的 Agent 團隊組態：

### 商業智能團隊

| Agent | 職能 |
|-------|------|
| 數據蒐集 Agent | 從你的工具拉取指標和 KPI |
| 分析 Agent | 找趨勢、異常和機會 |
| 報告 Agent | 把發現編成行政摘要 |
| 建議 Agent | 根據分析建議行動 |

### 客戶研究團隊

| Agent | 職能 |
|-------|------|
| 問卷設計 Agent | 設計研究問題 |
| 數據處理 Agent | 整理原始反饋 |
| 模式偵測 Agent | 找出重複出現的主題 |
| 洞察 Agent | 把模式轉化為產品建議 |

### 社群媒體團隊

| Agent | 職能 |
|-------|------|
| 趨勢監控 Agent | 監看你領域內的表現好的內容 |
| 內容規劃 Agent | 構建每週內容日程表 |
| 寫作 Agent | 替每個平台起稿 |
| 優化 Agent | 檢視並改進各貼文再發布 |

**每個團隊都遵循同樣的結構：** 專門化角色、清楚的指令、定義好的交接點。

## 核心原則總結

| 原則 | 說明 |
|------|------|
| **明確的角色** | Agent 的工作越專一，表現越好 |
| **詳細的指令** | 指令定義流程和品質標準，不只是目標 |
| **適當的工具** | 工具決定 Agent 在現實中能做什麼 |
| **持續反饋** | 反饋讓 Agent 隨時間進步 |
| **順序化工作流** | 一個 Agent 的輸出成為下一個的輸入 |
