# R17 子代理交付契約

> 決策記錄。對應規則已寫進 `d:\Claude\CLAUDE.md`（R16 之後）。

## 緣由

2026-06-29 水球課程入庫時，TaskC subagent 被交付 5 件事（寫 4 筆記 / 併 Force / 嵌 5 PNG / 更新課程總覽 / 不跑 refresh-index），實際只做了 1.5 件，但**回報只列「做了什麼」、未對照「被要求什麼」**，導致「更新課程總覽」與「嵌入 PNG」被**靜默跳過**，commit 後才被抓到。

**根因：**
1. 任務用散文列需求，不是可逐項勾選的清單
2. 回報格式沒強制逐項表態（做/跳過/失敗）
3. 編排者信任 agent 的敘述報告，未獨立驗證每個交付項

R10（驗證是強制步驟）、R12（失敗大聲說）已有原則，但未固化成派 subagent 的標準動作。

## 機制：交付契約表（跨三階段流動）

派 / 收 subagent 用**同一張表**：

| # | 交付項目 | 驗收指令（可直接跑） | 狀態 |
|---|---------|----------------------|------|

- **① 派工**（編排者填前三欄）：驗收欄寫**可執行指令**（如 `grep 代理 課程總覽.md`、`ls attachments/*.png | wc -l` == 5），能 pass/fail 就不寫文字描述
- **② 回報**（agent 填狀態）：逐列 `✅完成 / ⏭️跳過(註原因) / ❌失敗`，**不得增刪列**
- **③ 驗證**（編排者跑驗收指令）：親自跑、不看敘述就判定；全過才完成，任一未過不得進下一波

## 設計考量
- 核心槓桿在「③ 驗證」——派得再好 agent 仍可能漏，唯一 100% 攔得住的是編排者獨立驗證
- 驗收欄做成可執行指令 → 驗證變成跑指令、無需判斷，最難規避
- 同一張表不得增刪列 → 靜默跳過會缺號、立刻現形
- 觸發條件：≥2 交付項或需驗證才用；單一瑣事免（守 R2/R13）
