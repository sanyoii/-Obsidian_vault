## Step 0：移動前，先產生舊路徑清單

```powershell
# 範例：列出所有含舊路徑的檔案
$oldPaths = @("social-monitor","job-crawler","careerbot","hd-decode",
              "gbrain-skills","my-marketplace","brain-docs","Skill_origin")

  -Exclude node_modules | Select-String ($oldPaths -join '|') `
  | Select-Object Path,LineNumber,Line | Format-Table -AutoSize
```

**這份清單就是完成標準。** 移動後每一行都必須消失。

## 三個踩坑教訓

### 1. 平行檔要同輪處理

`setup.ps1` 和 `setup.sh` 是平行檔，必須在同一輪一起對照更新。同理：`*.html` 和 `*.md` 放在同一個 grep 裡掃，不要分 session 補。

### 2. 移動前先確認目錄類型

```bash
# 區分 gitlink（mode 160000）vs 一般目錄（mode 040000）
git ls-tree HEAD <dir>
```

- **gitlink**（如 hd-decode、careerbot）：用 `Move-Item` + `git rm --cached <old>` + `git add active/<new>`
- **一般目錄**（如 job-crawler、social-monitor）：可直接 `git mv`
- **深路徑（node_modules）**：改用 `robocopy /E /MOVE /256`

### 3. 移動前先確認目錄是否乾淨

```bash
git status  # 確認無 untracked 意外檔案
ls <dir>    # 確認沒有意外嵌套目錄
```

## 2026-06-17 進階重整教訓（.gitignore 錨定 + 大檔）

第二階段把結構從 ~85 推到 92 分（消滅 `Working Directory/`、命名正規化、加分類 README）。新踩到的坑：

### 4. .gitignore 錨定會暴露「一直被誤擋」的內容

不錨定的規則（`plugins/`、`plans/`）會 **case-insensitively 命中任意層級同名目錄**，造成兩種隱性 bug：
- `plugins/` 本意擋 `infra/plugins/`，卻連 `infra/my-marketplace/plugins/`（750 檔 marketplace 內容）一起擋掉 → marketplace 內容**從未進 git**、無法跨機器同步
- `projects/`（Claude runtime）case-insensitively 命中 `Working Directory/Projects/` → 害 `git add` 無法記錄該目錄刪除（要改用 `git rm --cached`）

**對策**：規則一律錨定到實際位置（`/infra/plugins/`）。**每錨定一條就立刻 `git status`**，確認沒有大量非預期檔案冒出來——冒出來的若是該追蹤的（marketplace）就 commit，若是垃圾（node_modules）就補 ignore。

### 5. 搬入專案前先估「生成媒體」體積

把 working dir 專案納入 git 前，先 `du -sh <project>/*` 看大檔。生成產物（圖檔/貼圖/`output/`/`dist/`/`.next/`/`preview.html`）**可重新生成、不該進 git**，比照 node_modules 加進 .gitignore。本次差點把 350MB 生成媒體推上公開 repo。

驗證：`git add --dry-run <dir>` 看實際納入數，再 `git diff --cached --numstat` 掃有無 >10MB 大檔。

### 6. 被鎖的空目錄不用糾結

搬完後源目錄空殼常被 file watcher/索引器鎖住無法刪。**空目錄不進 git、不影響驗證**，留待進程釋放即可，不要卡在這裡。

### 7. 順手抓 session 幽靈檔

heredoc/redirect 偶爾誤生成 0-byte 檔（如 `Sub-project`、`10MB`）。收尾 `git status` 時一併 `rm` 掉。
