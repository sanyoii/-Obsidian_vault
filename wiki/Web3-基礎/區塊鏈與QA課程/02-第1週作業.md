## 練習 B：Python 實驗

使用 [[wiki/Web3-基礎/區塊鏈與QA課程/01-第1週教材|教材程式]]，每題都重新從 Alice=10、Bob=0、Carol=0 開始。執行前寫下你猜會發生什麼，再把實際輸出貼在旁邊比較。做完一題，記得把上題改過的資料還原，再做下一題。

| 案例 | 輸入與起點 | 預測 | 實際輸出／快照 |
|---|---|---|---|
| B1 | 原始 T1→T2 與反向順序 | 待填 | 待填 |
| B2 | T2 改為 3；測兩種順序 | 待填 | 待填 |
| B3 | Alice=10，轉給 Bob 0 點 | 待填 | 待填 |
| B4 | Alice=10，轉給 Bob -1 點 | 待填 | 待填 |
| B5 | Alice=10，轉給 Bob 11 點 | 待填 | 待填 |
| B6 | Alice=10，轉給未建立的 Dave 1 點 | 待填 | 待填 |
| B7 | Alice=10，連續兩次付 Bob 3 點 | 待填 | 待填 |

做 B1、B2 時，保留教材最後兩行 `print("A:", ...)` 與 `print("B:", ...)`。B2 只把 `transfers` 裡 T2 的金額從 6 改成 3，兩種順序都跑一次。

做 B3–B6 時，保留 `apply_transfer` 與 `run` 的函式定義，把最後兩行 `print("A:", ...)` 與 `print("B:", ...)` 換成下面這段。這裡以 B3 的 0 點作為輸入；執行前先在表格寫預測。

```python
balances = {"Alice": 10, "Bob": 0, "Carol": 0}
before = balances.copy()
result = apply_transfer(balances, "Alice", "Bob", 0)
print("轉帳前", before)
print("程式回覆", result)
print("轉帳後", balances)
```

B4 把呼叫裡最後的 `0` 改成 `-1`；B5 改成 `11`。B6 把收款人 `"Bob"` 改成 `"Dave"`、金額改成 `1`，餘額表保持原樣。每題都重新執行這段，第一行會重設三人的起始餘額。比較「轉帳前」與「轉帳後」的每個人，再把程式回覆與餘額貼進表格。

B7 回到教材原程式，把最後兩行 `print("A:", ...)` 與 `print("B:", ...)` 換成以下整段。起始餘額只在第一行設定一次，第二次付款沿用第一次之後的餘額。先預測每次付款的結果，再執行。

```python
balances = {"Alice": 10, "Bob": 0, "Carol": 0}
print("起點", balances.copy())
result = apply_transfer(balances, "Alice", "Bob", 3)
print("第一次回覆", result)
print("第一次之後", balances.copy())
result = apply_transfer(balances, "Alice", "Bob", 3)
print("第二次回覆", result)
print("第二次之後", balances.copy())
```

這兩段是原有 B3–B7 的操作方式，放在第二堂「改資料與記錄」的 45 分鐘內完成。

B7 再想一想：使用者付了 3 點，因為沒看到回應，又把同一筆付款送了一次。這段程式能分辨嗎？如果他本來就想付兩次、每次 3 點，系統又該怎麼知道？請說明你還需要哪些資訊，才能決定要扣一次還是兩次。

程式跑不動時，把錯誤訊息連同手算結果貼回對話即可。還沒跑的欄位寫「未執行」，這樣才能分清楚你預測的結果和電腦實際做的事。

## 練習 D：不用區塊鏈可以嗎？

情境一：一間公司管理員工午餐點數，所有人接受公司負責更正錯帳。

情境二：幾個互不隸屬的組織要一起記錄資產轉給了誰，但大家還沒同意把記帳權交給其中任何一方。

每個情境各寫一段：你會選什麼系統？誰能改紀錄？記錯或有爭議時由誰決定？其他人要怎麼查帳？這個做法要付出什麼成本？

情境二的資訊還不完整。把你想問的問題也寫出來，例如誰能加入、資料能否公開、規則由誰決定；再說明這些答案會怎麼影響你的選擇。
