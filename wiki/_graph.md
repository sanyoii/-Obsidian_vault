## 連結記錄

### [[策略模式]] → [[開閉原則]]
**關係：** 實踐
**說明：** 策略模式是實踐 OCP 最直接的模式，外部注入行為 = 對擴充開放不修改核心
**建立於：** 2026-05-08（compile）

### [[策略模式]] → [[依賴反轉原則]]
**關係：** 實踐（重構三步驟）
**說明：** 依賴反轉之重構三步驟（封裝變動→萃取介面→委派）直接對應策略模式的結構
**建立於：** 2026-05-08（compile）

### [[策略模式]] ↔ [[樣板方法]]
**關係：** 對比（Forces 相近，解法不同）
**說明：** 同為行為變動的解法；策略用組合（注入），樣板用繼承（覆寫）
**建立於：** 2026-05-08（compile）

### [[策略模式]] ↔ [[責任鏈模式]]
**關係：** 對比（Forces 不同）
**說明：** 同為行為型，但策略處理「原始型」、責任鏈處理「輸入比對型」，Big 2 實戰精準區分
**建立於：** 2026-05-08（compile）

### [[樣板方法]] → [[依賴反轉原則]]
**關係：** 延伸（IoC 是 DIP 的框架層面體現）
**說明：** 控制反轉 (IoC) 是依賴反轉在框架設計中的表現形式
**建立於：** 2026-05-08（compile）

### [[觀察者模式]] ↔ [[指令模式]] ↔ [[狀態模式]]
**關係：** 共同學習（Ch 5 RPG 實戰）
**說明：** 三個模式在同一個 RPG 實戰專案中一起套用，相輔相成
**建立於：** 2026-05-08（compile）

### [[狀態模式]] ↔ [[策略模式]]
**關係：** 結構相似，意圖不同
**說明：** 兩者 UML 幾乎相同，但策略意圖在「替換演算法」，狀態意圖在「根據狀態改變行為」
**建立於：** 2026-05-08（compile）

### [[門面模式]] → [[整潔架構]]
**關係：** 實作
**說明：** 門面模式是整潔架構「封裝變化」方針在模組邊界的具體實作工具
**建立於：** 2026-05-08（compile）

### [[轉接器模式]] → [[整潔架構]]
**關係：** 實作（單向穩定依賴）
**說明：** 轉接器讓核心不直接依賴外部系統，實踐整潔架構的「單向穩定依賴原則」
**建立於：** 2026-05-08（compile）

### [[轉接器模式]] → [[依賴反轉原則]]
**關係：** 實踐（外部依賴場景）
**說明：** 轉接器是 DIP 在「核心 vs 外部系統」場景的具體工具
**建立於：** 2026-05-08（compile）

### [[裝飾者模式]] → [[開閉原則]]
**關係：** 實踐
**說明：** 新增裝飾者不修改核心物件，體現 OCP
**建立於：** 2026-05-08（compile）

### [[工廠方法]] → [[依賴反轉原則]]
**關係：** 實踐（創建型場景）
**說明：** 工廠方法讓核心依賴 Product 介面而非具體類別，DIP 在物件創建場景的應用
**建立於：** 2026-05-08（compile）

### [[開閉原則]] ↔ [[依賴反轉原則]]
**關係：** 互相依賴（SOLID 雙核）
**說明：** DIP 是實現 OCP 的底層機制；沒有 DIP（介面隔離）就無法真正做到 OCP
**建立於：** 2026-05-08（compile）

### [[物件導向分析]] → [[物件導向設計]]
**關係：** 前提（輸出→輸入）
**說明：** OOA 的領域模型是 OOD 的起點，OOD 加工 OOA 的產出
**建立於：** 2026-05-08（compile）

### [[水球流OADP]] → [[物件導向分析]] + [[物件導向設計]] + [[整潔架構]]
**關係：** 包含
**說明：** OADP 框架整合了 OOA、OOD、OOP 和設計模式套用，整潔架構是其架構層面延伸
**建立於：** 2026-05-08（compile）

### [[代理人模式]] ↔ [[轉接器模式]]
**關係：** 結構相似，Forces 不同
**說明：** 都在 Client 與 RealSubject 之間加一層；轉接器解決介面不相容，代理人解決存取控制
**建立於：** 2026-06-30（compile）

### [[代理人模式]] → [[開閉原則]]
**關係：** 實踐
**說明：** 新增存取限制只需新增 Proxy 類別，不修改既有程式碼
**建立於：** 2026-06-30（compile）

### [[複合模式]] → [[依賴反轉原則]]
**關係：** 實踐（套用三步驟）
**說明：** 複合模式的套用過程就是依賴反轉三步驟：萃取 Component 抽象→反轉依賴
**建立於：** 2026-06-30（compile）

### [[複合模式]] ↔ [[裝飾者模式]]
**關係：** 特化（裝飾者是複合模式的特殊形式）
**說明：** 同為結構型核心；複合解決樹狀結構擴充性，裝飾者解決行為疊加的組合爆炸
**建立於：** 2026-06-30（compile）

### [[單體模式]] ↔ [[開閉原則]]
**關係：** 張力（天然衝突）
**說明：** 單體的全域存取特性讓實作難以抽換，與 OCP 有天然張力；需搭配 DI 緩解
**建立於：** 2026-06-30（compile）

### [[抽象工廠]] → [[工廠方法]]
**關係：** 聚合升級
**說明：** 多次套用工廠方法後催生產品一致性 Force，聚合為抽象工廠
**建立於：** 2026-06-30（compile）

### [[抽象工廠]] → [[開閉原則]]
**關係：** 實踐
**說明：** 新增產品風格只需新增 ConcreteFactory，不修改既有程式碼
**建立於：** 2026-06-30（compile）
