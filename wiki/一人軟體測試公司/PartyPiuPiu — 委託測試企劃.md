## 委託目標與交付狀態

本案要找出活動主辦方、手機來賓與大螢幕操作過程中，會造成**無法參加、內容錯場、畫面失控、資料殘留或操作誤解**的問題，並提供可重現、可排序、可重測的改善依據。

本文件為 **v0.2 待委託方審閱企劃**。已完成公開網頁資料盤點；尚未登入、註冊、上傳、留言、清除或執行正式案例。32 個候選情境全為 Not Run。網站版本與規則仍待核對；目前僅有正式環境；帳號、時程與操作別復原由我們規劃與準備，具體建置見第13節；費用尚未報價。

建議先做「三端核心旅程＋風險導向探索」，再依結果補邊界、隔離與恢復測試。產品沒有購物流程的資料依據，本案不納入購物車、結帳或付款測試。

| REQ-07 複用與手動清除 | 複製專案產生新代碼與 QR；原專案清除名單留言後保留設定場景。 | 清除照片、舞台快取與進行中請求的範圍？可否復原？ |

## 缺陷、證據與交付方式

| 層級 | 判定例 | 處理提案 |
| --- | --- | --- |
| S1 阻斷／重大影響 | 活動無法進行、跨活動資料外洩或不可恢復誤刪 | 立即停止受影響測試，保留證據並由主責轉交客戶；外發仍按授權 |
| S2 主要功能 | 大量支援裝置不能自拍、舞台控制錯誤、資料規則失效 | 優先修正並重測；未解需客戶明確接受風險 |

證據鏈：REQ → RISK → TC → RUN → 截圖／錄影／紀錄 → 缺陷 → 新版重測。每次 Run 記時間、actor、方法、版本、定義快照、結果與原因；保留首次失敗，不以重測覆蓋。截圖去識別、日誌遮蔽 token／email；原始證據與報告分權保存，保存期限及傳送渠道由客戶確認。

- 正式測試後交付：測試摘要、缺陷清單、重現證據、覆蓋與未測項、重測紀錄、上線風險建議。
- 報告與證據先留本機；寄送、公開作品集或發布網站需另有明確授權。

1. 使用公司／使用者可控且可持續收信的信箱，先確認收信入口；可用別名時仍需各別完成驗證。禁止借用他人帳號或無法收回的臨時信箱。當前可用信箱與存取方式尚未確認，不能假稱已備妥。

3. 驗證註冊、收信、登入及登出；若產品有帳號找回功能，再用自有信箱驗證找回。若沒有該功能，記錄網站方的帳號救援途徑，不能猜已有重設入口。
4. 帳號找回尚未確認時，不測改密碼、改email、失效信箱或故意鎖帳號。QA-B只能提供工作備援，不能恢復QA-A原本的資料所有權。
5. 測試活動以 TEST-PP-A／TEST-PP-B 命名並記錄真正活動ID；QR、照片和留言不送到正式現場。退場時列清單，清除或停用另依已確認範圍執行。

### 寫入前的復原演練

先把唯一測試活動的可編輯欄位、角色池、顯示狀態與素材記錄成基準。選一個已確認可改回、僅影響該活動的設定，例如測試標題；若找不到這種設定，停止此演練，不改用刪除測試。

操作順序：記下原值 → 改一個測試值 → 讀回 → 改回原值 → 重整主辦端、來賓端與測試舞台 → 核對活動ID、設定與畫面。另確認本機網路限制解除後可以重新連線。逐項記錄實際耗時、差異和證據；不能只以「重新整理正常」當作回復成功。

通過這個演練只證明該設定與本機操作可復原，不證明自拍、留言、刪除、跨帳號或正式服務可以復原。每種新增操作都需先確認自己的回復路徑；沒有路徑的操作不進正式站。

### 出事時的處理順序

1. **立即停止所有測試寫入與重試**；不連續刷新、重送、改設定或嘗試大範圍清除。
2. 保留最後動作、時間、活動ID、瀏覽器／版本、回應與畫面；避免在證據中暴露帳密與真人資料。先判斷是我們設備、自建活動，還是共用服務異常；尚無證據時原因記 Unknown。
3. 只執行已演練且授權的回復動作：解除本機限制或改回自己的設定。結果不明先讀回；相同回復失敗一次即停止，不盲目重試。禁止還原整個正式資料庫或覆蓋期間新增的客戶資料。
4. 若超出我們可回復範圍，整理事故交接包交由使用者／指定窗口聯絡網站方。列最後已知正常時間、影響與待確認範圍、已做及未做動作。沒有外發授權時先交本機事故摘要，不自行聯絡他人。
5. 復原後核對三端可用性、活動歸屬、設定基準、資料完整性與是否殘留測試資料；跨客戶影響由網站方確認。保留原失敗，新Run記復原驗證。
6. 未確認回復、原因仍可能擴大影響或無技術窗口時，不恢復測試。重新確認環境、版本、剩餘額度與同意的測試範圍後才續跑。

復原時間目標（RTO）與可接受資料損失（RPO）目前未約定；本計畫記錄實際恢復時間，不宣稱幾分鐘內必定恢復或零資料損失。真正的後端還原不能靠UI截圖、HTML快照或重建測試活動替代。
