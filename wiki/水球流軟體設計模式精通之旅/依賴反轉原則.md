## 核心定義

**高層次（核心）的模組不能夠依賴低層次（衍生）的模組，兩者之間只能夠依賴一個抽象。**

依賴方向應永遠由衍生模組指向核心模組，而非相反。

---

## 詳細說明

### 重要性

> 課程定義：套用八成設計模式的**殺手級底層邏輯**

理解 DIP 就理解了大多數設計模式的骨幹。

### 傳統依賴方向（錯誤）

```
高層模組（核心） → 依賴 → 低層模組（具體實作）

問題：低層模組改變 → 高層模組被迫修改
```

### 反轉後（正確）

```
高層模組（核心） → 依賴 → 抽象介面 ← 依賴 ← 低層模組

效果：低層模組可自由替換，高層模組不受影響
```

### 水球課程：依賴反轉之重構三步驟

這是套用策略模式（及大多數設計模式）的具體操作手法：

1. **封裝變動之處** — 找出「會變的行為」，將其隔離
2. **萃取共同行為** — 定義抽象介面，描述這個行為「能做什麼」
3. **委派** — 讓核心類別持有介面而非具體實作，從外部注入
