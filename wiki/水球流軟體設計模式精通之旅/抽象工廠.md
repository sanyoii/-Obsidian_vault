# 抽象工廠 (Abstract Factory Pattern)

> **分類：** 創建型模式
> **標籤：** `#創建型` `#設計模式` `#產品一致性` `#工廠組合`
> **建立：** 2026-06-29
> **來源：** 水球軟體設計模式課程 Lesson 47 逐字稿 + 挑戰題 9B
> **課程章節：** Ch 9B（黑段道館）

## 核心定義

當程式中存在多個工廠介面（通常是套用多次[[工廠方法]]後產生），將這些工廠介面**聚合成一個抽象工廠介面**，強制同一組工廠方法的實作保持一致，確保創建出來的**產品組合**能有效協作來實現特定需求。

---

## 詳細說明

### 解決的 Forces

- **Force 1（多個工廠介面散落）**：因為套用了多次工廠方法模式，催生出許多工廠介面，程式中的各 Client 依賴著各種工廠介面
- **Force 2（產品組合一致性）**：這一組工廠介面生產的產品物件們，必須有一致的實作，才能實現某一高階意圖。但程式無法保證這件事——維護者可能不小心注入「實作不一致」的工廠組合，導致產品混搭出問題

### Problem

如何在程式中強制工廠組合的一致性，以致於創建出來的產品組合，能有效協作來實現個別需求？

### 結構（Form）

```
AbstractFactory（抽象工廠介面）
  ├── createProductA(): AbstractProductA
  ├── createProductB(): AbstractProductB
  └── ...

ConcreteFactory1 implements AbstractFactory
  ├── createProductA() → ConcreteProductA1
  └── createProductB() → ConcreteProductB1

ConcreteFactory2 implements AbstractFactory
  ├── createProductA() → ConcreteProductA2
  └── createProductB() → ConcreteProductB2

Client → 依賴 AbstractFactory 介面
        只需注入一個工廠物件，即可獲得實作一致的整組產品
```

### 與工廠方法的關係

| | 工廠方法 (Factory Method) | 抽象工廠 (Abstract Factory) |
|---|---|---|
| 處理的維度 | 單一產品的創建 | 一組相關產品的創建 |
| 解決的 Force | 物件生命週期約束 | 產品組合的實作一致性 |
| 典型演化 | 先套用工廠方法 | 多個工廠方法→聚合為抽象工廠 |

### Resulting Context

1. **強制一致性**：同一個 ConcreteFactory 產出的所有產品保證為同一「風格/版本/廠商」的實作
2. **一行切換**：Client 端只需更換注入的 ConcreteFactory，所有產品就統一替換
3. **OCP**：新增一組產品風格只需新增一個 ConcreteFactory，不修改既有程式碼

## 水球流教學重點

- 以「知識王爬塔闖關遊戲」為案例，逐步從需求分析推演到抽象工廠的必要性
- 每一樓層（Floor）需要創建多種產品：Region、Portal、Stage 等，且不同樓層可能使用不同廠商（Base vs. Super）的實作
- **關鍵問題**：如果每種產品各自獨立注入工廠，維護者可能混搭 Base 的 Region + Super 的 Portal，造成邏輯錯誤
- **解法**：將所有 Floor 相關的工廠方法聚合成 `FloorAbstractFactory`，提供 `BaseFloorAbstractFactory` 和 `SuperFloorAbstractFactory` 兩個具體實作
- 重構後：Main method 從需要六個實作類別變成只需兩個工廠物件，乾淨俐落

### 教學脈絡

課程刻意安排先學完多個行為型模式和結構型模式，最後在創建型模式副本中，讓學生體驗到：

1. 先多次套用[[工廠方法]]解決各自的創建問題
2. 發現多個工廠之間有一致性的 Force
3. 自然過渡到抽象工廠模式

## 實作要點

1. **先套用工廠方法**，為每種需要彈性創建的產品定義工廠介面
2. 觀察這些工廠之間是否存在「必須一致」的 Force
3. 如果存在，將它們**聚合成一個 AbstractFactory 介面**
4. 每個 ConcreteFactory **內聚地實作所有工廠方法**，保證產品組合一致
5. Client 只依賴 AbstractFactory，注入不同的 ConcreteFactory 即可切換整組產品

## 課程中的範例

- **知識王爬塔遊戲**：FloorAbstractFactory 聚合 Region、Portal、Stage 的創建，BaseFactory 對應基礎版，SuperFactory 對應進階版——每個樓層注入一個工廠就保證產品一致
- **挑戰題——ASCII 介面主題**（★）：ASCII UI 套件支援 Basic Theme 和 Pretty Theme，兩種主題分別決定 Button、NumberedList、Text 三種控制項的呈現方式。套用抽象工廠後，只需 `setAsciiTheme(基礎風)` 或 `setAsciiTheme(漂亮風)` 一行切換，即可統一替換所有控制項的渲染風格
