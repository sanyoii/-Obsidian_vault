## 核心定義

水球課程將《Clean Architecture》（Robert C. Martin）簡化為**兩大底層邏輯方針**，以應對需求變化而不讓系統腐化。

---

## 詳細說明

### 方針一：封裝變化

> 將「會一起變的、變法相同的」類別放進同一個模組，將變化收攏於一處。

- 高內聚：同一個業務關注點的程式碼放在一起
- 低耦合：不同業務關注點之間通過介面溝通
- 當需求改變時，影響範圍限定在一個模組內

### 方針二：單向穩定依賴原則

> 永遠由易變的衍生模組（插件、UI、應用端）依賴穩定的高階模組（核心領域）。

```
[易變] UI 層
[易變] 應用層
[穩定] 核心領域層
[易變] 基礎設施層（DB、API）
```

依賴方向：
- UI → 核心（✅）
- 基礎設施 → 核心（✅）
- 核心 → UI（❌ 禁止）
- 核心 → 基礎設施（❌ 禁止，用 [[轉接器模式]] 反轉）

### 與設計模式的關係

- [[門面模式]] — 模組邊界劃分的實作工具
- [[轉接器模式]] — 讓核心不依賴外部系統的具體工具
- [[依賴反轉原則]] — 單向穩定依賴是 DIP 的架構層面延伸
