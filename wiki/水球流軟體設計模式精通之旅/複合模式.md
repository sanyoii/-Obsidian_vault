## 核心定義

讓**樹狀結構**中的樹葉節點（Leaf）與複合節點（Composite）共同實作同一個抽象介面（Component），使 Client 能以統一的方式操作單一物件或整棵子樹，而不需要知曉結構的組成與變化。

---

## 詳細說明

### 解決的 Forces

- **Force 1（高結構複雜度）**：模型中存在遞迴關聯（Self Association），結構可無限延展——一層包一層永無止境
- **Force 2（結構變動性）**：結構中的類別組成會變（新增或汰換類別、改變關聯），存在 Structural Variation
- **Force 3（擴充性 + OCP）**：希望在擴充新的結構類別時，不影響 Client 和 Composite 的既有程式碼

### Problem

如何讓樹狀結構有良好的擴充性？並且不讓 Client 受到樹狀結構複雜度和變動性的影響？

### 何謂樹狀結構（Tree Structure）

滿足兩個條件即為樹狀結構：
1. 結構中存在至少一個遞迴關聯（Self-Association）
2. 結構為嚴格的階層關係，不能存在循環，每個物件最多只有一個父親

### 結構（Form）

```
Component（抽象類別/介面）
  ├── Leaf（樹葉節點）— 不具備兒子的類別
  └── Composite（複合節點）— 具備 Children（Component 類型）的類別
        ├── addItem(Component)
        ├── removeItem(Component)
        └── 行為只需針對 Component 撰寫

Client → 只依賴抽象的 Component
```

### 套用方式：依賴反轉三步驟

1. **萃取共同之處（Abstract What's Common）**：從結構中的多種類別萃取出共同的屬性與行為，形成 Component 抽象類別
2. **依賴反轉（Dependency Inversion）**：Composite 和 Client 的依賴對象從具體類別改為 Component 抽象

### Resulting Context

1. **去除冗餘**：Composite 類別不再針對不同種類兒子撰寫重複程式，行為統一對 Component 操作
2. **透明度（Transparency）/ Structure-Agnostic**：Client 不需要知道底層是單一物件還是一整棵子樹，什麼父子階層一概不 care——這是複合模式最迷人的性質

### 透明度 vs. 操作安全性（Tradeoff）

如果將 `addItem` / `removeItem` 提升到 Component 介面，Leaf 也必須實作（只能拋出例外），此時：
- **透明度提升**：Client 可以在任何 Component 上執行所有操作
- **操作安全性下降**：Client 可能不小心對 Leaf 呼叫 addItem 而導致例外

這兩項需求形成的 Forces **必定衝突**，必須做 **Tradeoff**——選擇影響較大的 Force 優先解決。

## 水球流教學重點

- 以「檔案系統 CLI」為案例：Directory（複合節點）和 File（樹葉節點）萃取出 Item 抽象類別
- 重構前：Directory 要分別管理 `fileChildren` 和 `dirChildren`，addFile/addDirectory/getFile/getDirectory 成雙成對冗餘
- 重構後：統一為一個 `Item Children List`，只需要 `addItem` 和 `getItem`，bytes 計算也變成一行
- CLI 的 `printSize` 從多個 if-else 簡化為直接 `getItem().bytes()`——不管是 Directory、File 還是未來的 Link
- 水球特別強調 **Agnostic** 這個字：「Structure-Agnostic」比「Transparent」更精確地表達 Client 的「不知道也不 care」

---

## 實作要點

1. **萃取 Component 抽象類別**，將所有結構成員的共同屬性和行為放入
2. **Composite 只持有 Component 類型的 Children List**，不區分具體子類型
3. Composite 的行為（如計算大小）透過遍歷 Children 呼叫 Component 上的抽象方法
4. Client 只依賴 Component，擴充新類別只需繼承 Component，不動 Client 和 Composite

## 課程中的範例

- **檔案系統 CLI**：Item（Component）← File（Leaf）、Directory（Composite）；CLI 作為 Client 統一對 Item 操作
- **挑戰題——日誌框架**（★★）：Logger 具備父子繼承關係；Exporter 本身就有複合結構（CompositeExporter 包含多個子 Exporter，也可嵌套 CompositeExporter）——複合模式的經典應用
